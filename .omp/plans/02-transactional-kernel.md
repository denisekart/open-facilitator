## Locked decisions (no implementer choice)

- **Layout:** all kernel code inside the existing `Facilitator` project (`src/facilitator/`), folders `Kernel/Domain`, `Kernel/Persistence`, `Kernel/Ingress`, `Kernel/Dispatch`, `Kernel/Auth`. One deployable; no new csproj except the shared validator inside existing `Ofac.Protocol`. Namespace root `Facilitator.Kernel.*`.
- **Migration tooling:** EF Core migrations, ONE baseline `InitialCreate`, applied **automatically on startup** (`await db.Database.MigrateAsync()` in `Program.cs`, guarded by config `Database:AutoMigrate`, default `true`) behind a singleton `IDatabaseInitializer` acquired via `pg_advisory_lock(420001)` so a future second replica doesn't race. `dotnet-ef` pinned via local tool manifest `.config/dotnet-tools.json`; design-time factory in `Kernel/Persistence/FacilitatorDbContextFactory.cs`.
- **EF Core specifics:** `NpgsqlDataSource` default; DbContext scoped; entity ids `uuid` (`Guid`) generated in C# (`Guid.NewGuid()`), timestamps `timestamptz` as `DateTime` UTC (`Npgsql.EnableLegacyTimestampBehavior` NOT set — always write `DateTimeKind.Utc`); jsonb columns via `.HasColumnType("jsonb")` storing `JsonNode`/`string`; schema `facilitator` (set `HasDefaultSchema("facilitator")`); connection string name `Facilitator` (`ConnectionStrings:Facilitator`, matching spec §22.2).
- **Ingress auth (pre-Keycloak, replaced in Plan 07 clean-cutover):** bootstrap shared token. Config `Auth:BootstrapToken` (string). Middleware `Kernel/Auth/BootstrapTokenMiddleware.cs`: every `/api/*` request must carry `Authorization: Bearer <token>`; 401 ProblemDetails otherwise. Single seam `IIngressTokenValidator` so Plan 07 swaps in OIDC by replacing the implementation only. `Auth:BootstrapToken` unset + environment Development ⇒ validator accepts `dev-token` (constant literal `"dev-token"`); non-Development with unset token ⇒ fail-closed 503 at startup. `/health` stays anonymous.
- **CLI:** the Facilitator assembly doubles as its own client. `Program.cs`: if `args[0] == "cli"`, run `Kernel/Cli/CliRunner` (no web host, no DB) and exit. Usage: `dotnet run --project src/facilitator -- cli [--url URL] [--token TOKEN] work create --objective "..." | work steer <id> --directive "..." --expect-version N | work get <id> | work timeline <id>`. Defaults `--url http://localhost:8088`, token from env `FACILITATOR_TOKEN` then `dev-token`. CLI calls the same HTTP API — no backdoor. (Chosen over a `referencectl` seed: the CLI is the slice-1 ingress, `referencectl` arrives in Plan 11.)
- **State-transition ingress:** beyond the roadmap's 4 endpoints, a generic `POST /api/works/{id}/transitions` (`{ "to": "<state>", "expectedVersion": N, "reason": "..." }`) is the operator-driven path that walks a Work through the full lifecycle over HTTP. Guard table below is the single authority; every transition appends an event envelope to the outbox.
- **Outbox addressing now:** `recipient_endpoint_id` values are logical channels; Plan 02 defines two: `"link.<endpointId>"` (unused until Plan 03 — dispatcher refuses, requeues, no dead-letter while no session table entry logic exists: treated as "no route", requeued with backoff) and `"kernel.log"` (stub sink target used by all Plan 02 transitions). Sink selection by prefix: `ISink` implementations registered per channel.
- **Envelope validation at ingress:** shared .NET validator in `protocol/dotnet/Ofac.Protocol/Validation/EnvelopeValidator.cs` — new dependency `JsonSchema.Net` (already in CPM at 9.4.1) added to `Ofac.Protocol.csproj`; schemas ship as `EmbeddedResource`s of `Ofac.Protocol` (the Facilitator image can't read `protocol/` at runtime). API: `EnvelopeValidator.CreateDefault()` → `Validate(EnvelopeCandidate)` returning `{ Ok, ErrorClass ∈ envelope-violation|schema-violation|payload-too-large|unknown-command, Message }` mirroring the fixture index `errorClass` enum. `KNOWN_COMMAND_TYPES` in C# (`Validation/KnownCommands.cs`): exact 7-type list from `src/protocol/src/validate.ts`. Update the csproj comment ("no runtime deps") accordingly. `Validate.Fixtures` may adopt it later — do NOT refactor it in this slice.
- **Idempotency:** CloudEvents dedupe `UNIQUE (event_source, event_id)` on `inbox`; business-command dedupe `inbox.command_id` unique when the payload is a command; provider path `provider_events` unique `(provider, provider_delivery_id)` when supplied (§7.1). Duplicate ⇒ 200 `{"status":"duplicate"}`, no reprocessing, no error (§7.1, appendix §5.6).
- **Per-Work serialization:** `SELECT pg_advisory_xact_lock(hashtext(work_id::text))` inside each processing transaction, then `UPDATE works SET version = version + 1 ... WHERE work_id = @id AND version = @expected`; 0 rows ⇒ optimistic conflict ⇒ typed 409; the processor retries once after rehydration (§7.4), the HTTP caller does not auto-retry.
- **Dispatcher:** single `IHostedService` (`OutboxDispatcher : BackgroundService`) inside the Facilitator process (no new container, §25.3 gate). Loop: poll interval 250 ms with exponential backoff to 5 s when idle, plus `Npgsql` `LISTEN facilitator_outbox` wake (NOTIFY = hint only). Claim: `SELECT ... FROM facilitator.outbox WHERE status='pending' AND available_at <= now() ORDER BY available_at LIMIT 20 FOR UPDATE SKIP LOCKED` then set `status='leased', lease_owner=@replicaId, leased_until=now()+interval '30 seconds', attempts=attempts+1` in the same short tx; deliver OUTSIDE any tx; on success `status='delivered', processed_at=now(), lease cleared`; on failure requeue `status='pending', available_at=now()+backoff` where `backoff = min(2^attempts * 2s, 5m)`; when `attempts >= 5` ⇒ insert `dead_letters` row (reason + full envelope snapshot) and `status='dead_letter'`. Expired leases (`status='leased' AND leased_until < now()`) are reclaimed by the same claim query predicate. `replicaId` = config `Kernel:ReplicaId`, default `machine-name + "/" + Guid` computed once per process.
- **Stub sink:** `KernelLogSink : ISink` for channel `kernel.log` — appends to an in-memory ledger (`DeliveryLedger` service: `record DeliveryId(outbox id), Attempts, DeliveredAt`) AND logs; exposes `GET /api/dev/deliveries` (bootstrap-auth'd, Plan 12 replaces with admin views) so restart/dedup tests assert drain and per-outbox-id exactly-once *successful* delivery.
- **Observability baseline (Plan 11 becomes config-only):** `OpenTelemetry.AspNetCore` meta-package; `builder.Services.AddOpenTelemetry().WithMetrics(...).WithTracing(...)`; OTLP exporter active when `Otel:Endpoint` set (matches spec §22.2 env `Otel__Endpoint`), otherwise console-off/noop. Instruments (exact names, appendix §9.1): counters `facilitator.delivery.attempts`, `facilitator.inbox.processed`; histograms `facilitator.delivery.latency`, `facilitator.ingress.processing.latency`; gauges (via observable callbacks counting DB rows on demand) `facilitator.outbox.queue_depth`, `facilitator.inbox.queue_depth`, `facilitator.delivery.dead_letter_count`. Trace spans: `ingress.process`, `outbox.dispatch`. Log scope enrichment: `workId`, `assignmentId`, `deliveryId`, `traceparent` (appendix §9.2). Activity source name `Facilitator.Kernel`; meter name `facilitator`.
- **Error contract:** all API errors are RFC 9457 `ProblemDetails` with `type` URIs under `https://errors.openfacilitator.org/v1/...`: `invalid-state-transition` (422), `version-conflict` (409), `unknown-command` (422), `schema-violation` (400), `envelope-violation` (400), `payload-too-large` (413), `duplicate` (200, not a problem), `unauthorized` (401), `work-not-found` (404).
- **Payload limit:** ingress reads bodies with `MaxRequestBodySize` 262144; oversize ⇒ 413 `payload-too-large` (aligns fixture `limits.maxEnvelopeBytes`).

## Step 2 — Domain + persistence seams

- `Kernel/Domain/WorkState.cs` / `AssignmentState.cs`: enums + `StateGuard` static tables — EXACT legal transitions, no implicit jumps (skill: "do not invent shortcuts"):
  - Work: `open→planning`, `planning→active`, `active→review`, `review→completed`, `open→blocked`, `planning→blocked`, `active→blocked`, `blocked→planning`, `blocked→active` (resume to last non-blocked predecessor tracked in `work_events`), `open|planning|active|review|blocked→cancelled`, `open|planning|active|blocked→failed`. Terminal: `completed|cancelled|failed`.
  - Assignment: full §4.1 chain `proposed→routed→accepted→running→{input_required,completed,failed,cancelled,expired}`, `input_required→running|cancelled|expired`, `running→running` illegal (generation bump instead).
- `Kernel/Persistence/ICoordinationStore.cs` (§20): `Task<Work> CreateWorkAsync(NewWork, CancellationToken)`, `Task<TransitionResult> ApplyTransitionAsync(Guid workId, WorkState to, long expectedVersion, string actor, string? reason, CancellationToken)`, `Task<SteerResult> ApplySteerAsync(Guid workId, string directive, string commandId, long expectedVersion, ...)`, `Task<WorkView?> GetAsync(...)`, `Task<IReadOnlyList<WorkEventRow>> TimelineAsync(...)`. All mutating methods = one transaction: advisory xact lock on workId → version check + increment → state/guard update → `work_events` append → outbox append → commit.
- `Kernel/Dispatch/IEventDispatcher.cs` (§20 surface): `Task<int> DrainOnceAsync(CancellationToken)` (claim+deliver one batch, returns delivered count) + `Task<int> ReclaimExpiredLeasesAsync(...)`. The `BackgroundService` loop is a thin timer over these — unit-testable without the host, and the restart test calls `DrainOnceAsync` against a stopped host to simulate a crashed dispatcher.
- `Kernel/Dispatch/ISink.cs`: `Task<bool> DeliverAsync(OutboxRow row, CancellationToken)` — true=delivered. `KernelLogSink` per locked decisions.
- Outbox event payloads are full CloudEvents envelopes (validate with `EnvelopeValidator` before insert — kernel emits conformant envelopes, tested against the Plan 01 harness). Envelope construction helper `Kernel/Domain/EnvelopeFactory.cs`: `source` = `urn:facilitator:kernel`, `subject` = workId, types from the Plan 01 list (`org.facilitator.event.work.progress.v1` etc.), `dataschema` = matching `$id`, extensions `traceparent` (from `Activity.Current`), `correlationid`, `causationid`. ## Step 3 — Ingress (`Kernel/Ingress` + endpoints in `Program.cs`)

Pipeline for every write endpoint (appendix §5.3, spec §19.3): validate envelope/body → insert `inbox` row (`ON CONFLICT (event_source,event_id) DO NOTHING`; conflict ⇒ 200 `{"status":"duplicate","inboxId":...}`) → **process inline in the same request** via `IngressProcessor` (slice 1 is synchronous-by-design; §20 "each incoming event triggers an independent iteration" — the iteration happens per request, no background inbox poller needed yet, but `inbox` rows exist so a Plan 16+ poller can take over) → after commit, `NOTIFY facilitator_outbox` (wake dispatcher). Inline processing uses the exact same `ICoordinationStore` transactions the future poller uses.

Endpoints (all `app.MapGroup("/api")`, bootstrap-auth'd, ProblemErrors above):
- `POST /api/works` `{ "objective": "...", "projectId": uuid? }` ⇒ 201 `WorkDto`. Internally: synthetic inbox row (source `urn:facilitator:http`, fresh CE id, commandId = client-supplied `commandId` optional, default server-generated) so creation participates in dedupe; Work at `open`, version 1, timeline `created` event, outbox `work.progress` to `kernel.log`.
- `GET /api/works/{id}` ⇒ 200 `WorkDto {workId, projectId, objective, state, version, createdAt, updatedAt}`; 404 typed.
- `POST /api/works/{id}/steer` `{ "directive": "...", "commandId": "...", "expectedVersion": N }` ⇒ 200 `WorkDto` (version bumped) | 409 `version-conflict` (body carries `currentVersion`) | 404 | 422 on terminal-state Work. `commandId` re-post ⇒ 200 `{"status":"duplicate"}` with the stored result.
- `POST /api/works/{id}/transitions` `{ "to": "planning", "expectedVersion": N, "reason": "..." }` ⇒ 200 `WorkDto` | 422 `invalid-state-transition` (message names the illegal edge) | 409 | 404.
- `GET /api/works/{id}/timeline` ⇒ 200 array of `work_events` rows ascending.
- `POST /api/ingress/events` — CloudEvent envelope body (any type from the Plan 01 corpus). Steps: size ≤ 262144 ⇒ else 413; `EnvelopeValidator.Validate`; command type not in `KnownCommands` ⇒ 422 `unknown-command` (fail closed, §5.5) AND still persist an `inbox` row with state `failed` (audit record, §5.4); valid command ⇒ inbox insert + inline process (only `work.steer` v1 maps to a business effect this slice: routes to `ApplySteerAsync`; other valid commands ⇒ 202 with inbox row `processed` and a timeline no-op note — typed, not silent); valid event ⇒ inbox insert, 202, no side effects. Response 200 `{"status":"accepted","inboxId":...}` | `{"status":"duplicate",...}`.
- `GET /api/dev/deliveries` — `DeliveryLedger` dump.
- Keep `GET /health` anonymous (liveness only; Plan 11 healthcheck).
- `GET /api/works` (list, newest 50) for Plan 12 convenience — one-liner, include it.

`Program.cs` restructure: keep `public partial class Program;`; add DI (`KernelServiceCollection` extension), auth middleware before endpoints, OTel, migrate-on-startup, `HostedService` registration. CLI branch before web host.
