## Context

The kernel (Plan 02) persists outbox rows addressed `link.<endpointId>` that its dispatcher currently refuses as "no route" (requeues forever, `src/facilitator/Kernel/Dispatch/DbEventDispatcher.cs` `HandleFailureAsync`, `noRoute: true`). Plan 03 builds the Facilitator side of the Workspace Link so those rows reach live endpoints: enrollment with per-endpoint link tokens, `link_sessions` lease records (§7.3), the SignalR hub (`Hello`/`Envelope`/`Receipt`/`Heartbeat` server methods; `Welcome`/`Deliver`/`FlowControl`/`Disconnect` client methods, S:294) plus the provider-neutral HTTP fallback frozen in `protocol/openapi/link-v1.yaml`, a durable delivery/receipt ledger that makes redelivery and replay correct (S:291 "resume cursor is a hint, receipt ledger is truth"; appendix A:155-157), `maxInFlight` backpressure (S:304), link-ingress of worker-originated envelopes into the kernel inbox, and a dead-letter visibility endpoint (A:157). End state: a scripted fake link client can enroll, hello/welcome, receive a queued `work.assign` delivery, post a receipt, die, reconnect with a new epoch, and get replayed exactly the un-acked deliveries. Spec slice-2 server half + §26.1 items 2–3 (server side) pass.

## Locked decisions (no implementer choice)

- **Layout:** all server code inside the existing `Facilitator` project, new folders `src/facilitator/Kernel/Link/` (hub, pump, ledger, enrollment) + one migration. Namespace root `Facilitator.Kernel.Link`. No new csproj. SignalR ships in the ASP.NET Core shared framework — no new NuGet for hub/server; check `Directory.Packages.props` before assuming otherwise (frameworkreference-free since `Microsoft.NET.Sdk.Web`).
- **Interim link auth (clean-cutover seam for Plan 07):** `ILinkTokenValidator` in `Kernel/Link/LinkAuth.cs`: `Task<LinkPrincipal?> ValidateAsync(string token, CancellationToken)` where `LinkPrincipal(string EndpointId, Guid TeamId, string TrustMode)`. Implementation `StoreLinkTokenValidator` hashes bearer tokens (SHA-256) and looks them up in the new `link_enrollments` table (below). Plan 07 replaces the implementation with OIDC validation + `principal_mappings`; call sites unchanged. Registration: new `LinkAuthMiddleware` (or per-endpoint filter) guards `/api/link/v1/*` EXCEPT `POST /api/link/v1/enroll`, which is guarded by the **bootstrap enrollment secret** from config `Link:EnrollmentToken` (env `Link__EnrollmentToken`; unset + Development ⇒ literal `"enroll-dev"`; unset + non-Development ⇒ fail-closed 503 at startup, mirroring `Auth:BootstrapToken`). The kernel API bearer (`Auth:BootstrapToken`, Plan 02 middleware) keeps guarding `/api/*` **except** `/api/link/v1/*` — cut over `BootstrapTokenMiddleware` to skip the link path prefix (one condition; note the path overlap deliberately). Hub: token via `Authorization` header during negotiation AND `?access_token=` only as documented fallback for the WS-only case (S:624: server-side clients send headers; no secrets in query strings for our TS clients — document).
- **Enrollment wire contract (user-approved amendment):** `protocol/openapi/link-v1.yaml` — add **optional** properties `linkToken` (string, 1..4096) and `expiresAt` (date-time) to `EnrollResponse`; bump `info.version` to `1.0.1`; keep `additionalProperties: false`. The server ALWAYS returns both (HS256-less opaque random token, 256 bits base64url; `expiresAt` = now + config `Link:TokenLifetimeHours`, default 720). Re-enrolling the same `endpointId` rotates the token (old token stops validating immediately) — this is the §26.1 item 2 token-invalidation lever. `EnrollRequest.token` = the bootstrap enrollment secret. Response also gains nothing else; the appendix A:101-108 record fields (`gatewayId→endpointId`, `capabilityManifestDigest`, `enrolledAt`, `trustMode`) are stored **server-side**, not returned.
- **New table `link_enrollments`** (migration `AddLinkServer`, second migration, no re-baseline): `enrollment_id uuid PK`, `endpoint_id text NOT NULL UNIQUE`, `team_id uuid NOT NULL FK teams`, `token_sha256 text NOT NULL`, `trust_mode text NOT NULL` CHECK `shared-runtime|separate-process-same-host|isolated-executor`, `capability_manifest jsonb NULL`, `capabilities_digest text NULL`, `enrolled_at timestamptz NOT NULL`, `expires_at timestamptz NOT NULL`, `revoked_at timestamptz NULL`. First team auto-provisioned: if no `teams` row, enrollment with unknown team binds to a team seeded on demand with slug `"default"` (Plan 11 proper seeding replaces this; note in code comment).
- **New table `link_deliveries`** (the `delivery_receipts` of S:1336 — the durable delivery/receipt ledger): `delivery_id uuid PK` (= outbox row id, FK outbox), `endpoint_id text NOT NULL`, `session_epoch bigint NOT NULL` (epoch of the session that last carried it), `state text NOT NULL` CHECK `pending|in_flight|acked`, `delivered_at timestamptz NULL`, `acked_at timestamptz NULL`, `receipt jsonb NULL` (last receipt verbatim), `attempts integer NOT NULL DEFAULT 0`, `redeliver_after timestamptz NULL` (in-flight lease deadline). Index `(endpoint_id, state)`. **Delivery identity = outbox id**, so a receipt for an already-`acked` delivery answers the LATEST attempt — the "dropped receipt → redelivery → duplicate" loop terminates.
- **Session model:** `link_sessions` (exists: `logical_endpoint_id` PK, `connection_instance_id`, `replica_id`, `session_epoch`, `lease_until`, `last_heartbeat`, `capabilities_digest`) is updated on `Hello` with `session_epoch = max(existing)+1`, `lease_until = now() + heartbeatSeconds*3` (clamped ≥ 15 s), `replica_id = Kernel:ReplicaId` (already in Plan 02 config). Heartbeat refreshes `lease_until` + `last_heartbeat` ONLY for a matching `(endpoint_id, session_epoch)`; stale epoch ⇒ hub sends `Disconnect` (client method, reason `"session-superseded"`) and closes; HTTP caller gets 409 ProblemDetails `session-superseded`. A second `Hello` for the same endpoint while a live session exists **supersedes** it (bumps epoch, notifies old connection `Disconnect`, spec §16.2 "restarts re-use logical ID, get new session + epoch"). `goodbye` (client→server via `Envelope` method or `Goodbye` hub method) revokes the session row and acks nothing.
- **Handshake semantics:** `Hello(HelloFrame)` → validate against `control.v1.json` (embedded schema via `Ofac.Protocol`); negotiate `protocolVersion` = intersection of `protocolVersions` with server-supported `["v1"]`; empty ⇒ typed goodbye: mint a session id (do NOT insert a `link_sessions` row), push the client method `Disconnect` carrying the frozen GoodbyeFrame `{kind:"goodbye", sessionId:<minted>, reason:"no-compatible-protocol-version"}` (fixture `invalid/control.hello.v9-only.json` → expected `valid/control.goodbye.incompatible.json`), and return `null` from `Hello` (`WelcomeFrame?`). Document the null-return convention in `docs/protocol.md`. Success ⇒ insert/update `link_sessions`, reply `WelcomeFrame{kind:"welcome", sessionId=Guid N, leaseEpoch, maxInFlight, heartbeatSeconds, protocolVersion}`. Config: `Link:MaxInFlight` default 16, `Link:HeartbeatSeconds` default 30 (validate 5..600). Then immediately pump pending deliveries (§5.3 step 4: fetched from the DB receipt ledger, `lastKnownAck` ignored as proof — implementer MAY accept the field and log it as a hint).
- **Deliver frame shape (spec silence → frozen here):** SignalR `Deliver` client-method payload = the SAME JSON object as the OpenAPI `Delivery` component: `{"deliveryId":"<outboxId:N>","envelope":{...CloudEvent...},"deliveredAt":"...Z"}` — reuse one C# record `DeliveryDto(Guid DeliveryId, JsonElement Envelope, DateTime DeliveredAt)` camelCase, in `Kernel/Link/LinkDtos.cs`, shared by hub push and HTTP GET. "Durable delivery metadata" = `deliveryId` + `deliveredAt` (§5.2 S:278: receipt references the durable deliveryId).
- **`Envelope` hub method + `POST /api/link/v1/events` (identical semantics):** body = CloudEvent JSON. Pipeline: 262144-byte cap ⇒ 413/`payload-too-large`; `EnvelopeValidator.Validate` ⇒ 400 with errorClass-mapped ProblemDetails (`envelope-violation`, `schema-violation`); type in `KnownCommands` (7-type table) ⇒ route to a **link-specific IngressProcessor admission** (reuse `IngressStore.TryInsertInboxAsync` + dedupe response) with these effects: `work.steer` → same `ApplySteerAsync` path as Plan 02 ingress; `work.assign` arriving FROM a link is illegal (assign is kernel→link only) ⇒ 422 `unknown-command`-style typed `unsupported` receipt; other 6 known commands ⇒ 202/`{"status":"accepted"}` inbox row `processed` no-op (Plan 02 precedent: typed, not silent). Type matching `org.facilitator.event.*.v1` ⇒ inbox insert, 202 accepted, no side effects yet. Unknown `command` type ⇒ 422 typed `unsupported` ProblemDetails (error URI `https://errors.openfacilitator.org/v1/unsupported`) AND inbox row state `failed` (audit, S:305). Receipt class frames over this method ⇒ 400 `envelope-violation` (receipts travel via `Receipt`/receipt endpoint, not envelopes). Response code 202 on admission (OpenAPI frozen: 202 + receipt body `{deliveryId, status, processedAt}` — for HTTP-posted envelopes the `deliveryId` is the inbox row id string, documented). HTTP fallback needs NO handshake: enrollment + bearer token IS the session bootstrap; HTTP principals get no `WelcomeFrame` (spec silence: `heartbeatSeconds` lease for HTTP principals refreshed implicitly on every `/deliveries` call — a 404 `session-not-found` ProblemDetails if no live `link_sessions` row or lease expired; enroll-then-poll without handshake would 404, documented).
- **`Receipt` hub method + `POST /api/link/v1/deliveries/{id}/receipt` (identical):** body validates against `receipt.v1.json` (minus `deliveryId` on HTTP path — identity from path; hub method passes the full frame). Server: look up `link_deliveries` by deliveryId, must belong to the caller's endpoint (else 404 `delivery-not-found` ProblemDetails). Record receipt jsonb, `state='acked'`, `acked_at`, AND set matching outbox row `status='delivered', processed_at, last_error=NULL` in ONE transaction (dispatcher must not double-charge). Receipt for an `acked` delivery ⇒ 204 idempotent (receipt ledger truth, second receipt overwrites `receipt` jsonb, timeline-free). Receipt for unknown id ⇒ 404. HTTP 204 / hub method returns void. `duplicate` receipt ALSO terminates redelivery (the client saw the command before — ledger semantics identical; note in docs).
- **GET `/api/link/v1/deliveries?wait&limit`:** claims up to `min(limit, session.maxInFlight - inFlight)` rows from `link_deliveries` for the caller's endpoint: predicate `state='pending' OR (state='in_flight' AND redeliver_after < now())`, `ORDER BY delivered_at NULLS LAST, delivery_id`, `FOR UPDATE SKIP LOCKED`, set `state='in_flight'`, `session_epoch`=caller epoch, `delivered_at=now()`, `redeliver_after = now() + Link:InFlightLeaseSeconds` (config, default 120), `attempts+=1`. `wait` seconds long-poll: `Channel<long>` per-endpoint wake fired by the pump after inserts + a 1 s polling safety net (NOTIFY hint only, §7.3); empty on timeout ⇒ 200 `[]`. Redelivery on in-flight-lease expiry IS the dropped-receipt mechanism (S:302).
- **Pump (`LinkDeliveryPump : BackgroundService` + on-demand):** materializes outbox rows addressed `link.<endpointId>` into the ledger **only while a live session exists** (`link_sessions.lease_until > now()`). Materialization SQL (insert-or-ignore on `delivery_id`, idempotent): `INSERT INTO link_deliveries SELECT o.outbox_id, substring(o.recipient_endpoint_id from 6), s.session_epoch, 'pending', NULL, NULL, NULL, 0, NULL FROM facilitator.outbox o JOIN facilitator.link_sessions s ON s.logical_endpoint_id = substring(o.recipient_endpoint_id from 6) WHERE o.recipient_endpoint_id LIKE 'link.%' AND o.status NOT IN ('delivered','dead_letter') AND NOT EXISTS (SELECT 1 FROM facilitator.link_deliveries d WHERE d.delivery_id = o.outbox_id)` — the pump never mutates the outbox row (the receipt transaction owns its terminal state, below); selecting `status NOT IN (delivered,dead_letter)` covers rows the dispatcher holds `leased` to `LinkSink` so both views converge on the ledger as the single delivery truth. Un-acked link outbox rows stay non-`delivered` while the link is down — "no outbox row becomes permanently tied to a dead socket" (§7.3): on reconnect + fresh materialization/claim they are re-offered from Postgres. The pump runs: after every `Hello`, on every `NOTIFY facilitator_outbox`, on a 2 s safety poll, and inline before a `/deliveries` claim. Pump = the sole owner of link-channel delivery state transitions except the receipt ack.
- **`LinkSink : ISink` (`Channel => "link"`):** the entire sink contract is a routing liveness probe — `DeliverAsync` resolves the endpoint segment of `recipient_endpoint_id`, runs `SELECT EXISTS (SELECT 1 FROM link_sessions WHERE logical_endpoint_id = @endpoint AND lease_until > now())`, returns `true` (a live session owns this row via the DB, pump will materialize/deliver) or `false` (no session anywhere → Plan 02's existing no-route requeue-with-backoff applies unchanged, dispatcher code untouched). Ordering, redelivery, and attempt accounting for link rows all live in `link_deliveries`, not the dispatcher.
- **Flow control:** on in-flight count reaching `maxInFlight` the server pushes client method `FlowControl{kind:"flow_control",sessionId,maxInFlight:0}` (pause, frozen schema allows 0); when a receipt frees capacity ⇒ `FlowControl{...maxInFlight:configured}` (resume). The claim-side window already enforces the cap (GET and pump both bound by `maxInFlight - inFlight`); the frames are advisory hints for the client's own pacing (fixture `valid/control.flow_control.json` shape).
- **Heartbeat hub method:** `Heartbeat(HeartbeatFrame{kind,sessionId,leaseEpoch})` ⇒ refresh lease + `last_heartbeat`; stale epoch/session ⇒ `Disconnect` push + return false (client must re-`Hello`). SignalR keepalive: server-wide `KeepAliveInterval`/`ClientTimeoutInterval` set from `Link:HeartbeatSeconds` defaults at `AddSignalR` (server options are global, not per-connection; the per-session `heartbeatSeconds` in `Welcome` governs the CLIENT's send cadence and the DB `lease_until` window). Authoritative liveness is the DB lease, not socket state: a sweeper tick inside the pump closes (registry `CloseAsync` + `Disconnect` push) any tracked connection whose `link_sessions.lease_until` has passed — §7.3 lease expiry, not TCP, ends a session.
- **GET `/api/link/v1/capabilities`:** 200 with the stored `capability_manifest` jsonb; 404 `capabilities-not-found` if the enrollment never supplied one. Manifest supplied via **`POST /api/link/v1/capabilities`** (additive OpenAPI path, same auth, body validated against `capability-manifest.v1.json`, `ownerTeam` MUST equal the principal's team slug ⇒ 403 `team-mismatch` otherwise; stores jsonb + SHA-256 digest, 204).
- **Dead-letter visibility endpoint:** `GET /api/dead-letters` (bootstrap-kernel-token auth, kernel API group): array `{deadLetterId, outboxId, reason, envelope, createdAt}` newest 50. Appendix §5.6 MUST satisfied; Plan 12 admin UI consumes it.
- **Observability (appendix §9):** new span name `link.handshake` on the `Facilitator.Kernel` activity source (tags `facilitator.endpoint_id`, `facilitator.session_epoch`, `facilitator.protocol_version`); new counters on the existing `facilitator` meter (names exact, appendix §9.1): reuse `facilitator.delivery.attempts` for link claims; new `facilitator.link.sessions` observable gauge (live session count) and `facilitator.link.received` counter (envelopes admitted). Log `trustMode` at enrollment AND every Hello (A:112).
- **Error URIs (extends Plan 02 table, same ProblemDetails shape):** `unsupported` (422), `session-superseded` (409), `session-not-found` (404), `delivery-not-found` (404), `capabilities-not-found` (404), `team-mismatch` (403), `enrollment-secret-invalid` (401), `no-common-version` (409, HTTP-surface equivalent of the goodbye frame — SignalR path sends the goodbye instead).
