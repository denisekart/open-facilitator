## Context

Plans 05–07 shipped three real runtimes (`ofac-gateway`, `ofac-linkd`, `ofac-deterministic-worker`) but they are only runnable from a repo clone. Spec §8 promises distribution: *adding one Feature to an existing `devcontainer.json` yields a linked, headless workspace* (§28's onboarding law). This plan ships `features/src/{gateway,workspace-link,harness-adapter}` as OCI-published Dev Container Features that install those binaries (baked-in tarball layers — no npm registry dependency at install), a headless supervisor entrypoint (§8.2: never rely on lifecycle hooks), and `examples/slim/deterministic-research-worker/.devcontainer` as the composed example. No new runtime behavior, no new wire types — packaging only. Closes Phase B.

## Locked decisions (no implementer choice)

- **Layout:** `features/src/<name>/{devcontainer-feature.json,install.sh,README.md}` (distribution-spec `src/` convention; enables `devcontainer features publish` straight from `features/src`). Delete the three `.gitkeep`s and rewrite the stale READMEs. Feature ids `ofac-gateway`, `ofac-workspace-link`, `ofac-harness-adapter`; `version: "1.0.0"` (Feature version ≠ protocol major, §8.5); `installsAfter` on harness-adapter → gateway, on workspace-link → gateway (deterministic install order for unit files).
- **Install payload:** a repo-root build step (`features/build.mjs`) runs `pnpm -r build`, then `pnpm deploy --filter=@ofac/<pkg> --prod <tmpdir>` per Feature (`gateway`→`@ofac/gateway`, `workspace-link`→`@ofac/workspace-link`, `harness-adapter`→`@ofac/harness-deterministic`), and tars each deployed tree to `features/src/<name>/pkg/runtime.tar.gz` (+ `sha256sum` sibling `pkg/runtime.tar.gz.sha256`). `pkg/` is `.gitignore`d, generated before `features test`/`publish`. Install runs as root: verify checksum, `mkdir -m 0755 /usr/local/lib/openfacilitator/<name>`, extract there, symlink `ln -sf /usr/local/lib/openfacilitator/<name>/node_modules/.bin/<bin> /usr/local/bin/<bin>` (verify the deployed `.bin` layout after the first `pnpm deploy`; if pnpm emits a different bin path, adapt the symlink — the observable law is: `ofac-*` on PATH, `command -v` passes). Node deps (incl. better-sqlite3 prebuilds) ride inside the deployed tree — **no npm install, no network, no toolchain** at Feature-install time.
- **Node prerequisite:** each `install.sh` hard-fails (exit 1, actionable message) unless `node` on PATH reports major ≥ 22. No Feature-installed Node runtime: base images from `mcr.microsoft.com/devcontainers/base` ship Node, and the spec's "small Node.js runtime if missing" is satisfied by documenting the base-image expectation in each README. Simple over clever: a Feature-downloading nodejs.org tarballs adds build-time network + checksum policy for zero benefit in the tested matrix.
- **Supervisor (one mechanism, no process manager):** each install.sh drops an identical, idempotent `install -m 0755` copy of `features/shared/ofac-supervisor.sh` at `/usr/local/share/openfacilitator/ofac-supervisor.sh`, plus its own unit at `/usr/local/share/openfacilitator/units/<NN>-<name>.sh` (`10-gateway.sh`, `20-linkd.sh`, `30-harness-adapter.sh`). Supervisor: POSIX sh — logs to `${OFAC_LOG_DIR:-/tmp/openfacilitator/logs}/<unit>.log`, launches each unit file (sorted) in the background, `trap`s TERM/INT forwarding it to children, `wait`s, exits with the first non-zero unit exit. Units are plain loops: gateway/linkd/worker already carry their own retry/backoff laws, so the supervisor restarts an exited unit after 2 s (`OFAC_SUPERVISOR_MAX_RESTARTS` default 10, then give up and log). `gateway` and `workspace-link` and `harness-adapter` each declare `"entrypoint": "/usr/local/share/openfacilitator/ofac-supervisor.sh"` (identical strings).
- **Options (startup-only; runtime config/env stays the truth):**
  - `gateway`: `configPath` (default `.facilitator/gateway.yaml`, baked into the unit as `GATEWAY_CONFIG` fallback, overridable at runtime by the env), `log` (`info|debug`, default `info` → exports `OFAC_GATEWAY_LOG=debug` in the unit when `debug`).
  - `workspace-link`: `facilitatorUrl` (default `http://localhost:8088`), `endpointId` (default `ws.dev`), `team` (default `default`), `manifest` (default `.facilitator/capabilities.yaml`; unit passes `--manifest` only if the file exists at start — linkd treats manifest as optional, confirm against `src/workspace-link/src/bin/linkd.ts` arg parser and match its as-built requirement), `mode` (`echo|stub`, default `echo`). Every option value is baked as the unit script's default; the matching `OFAC_*` env var still wins at runtime (secrets never options: `OFAC_ENROLL_SECRET`/`OFAC_LINK_TOKEN` only, per §8.2 no-secrets-at-build).
  - `harness-adapter`: `adapter` (default `deterministic`; install.sh rejects any other value exit 1 — the only adapter binary that exists), `configPath` (default `.facilitator/harness.yaml`, unit runs `ofac-deterministic-worker run --config <path>`).
- **No lifecycle-hook commands** declared by any Feature (§8.2 law; supervisor entrypoint covers IDE and headless alike).
- **State law:** Features own no state; generated/example configs point `stateDir`/`workDir` at the workspace mount (`.ofac-gateway`, `.ofac-worker`), matching the existing manual-path example.
- **Publish:** `release.yml` gains a `features` job (same tag trigger, permissions, login as `containers`): `pnpm install && pnpm -r build && node features/build.mjs && npx --yes @devcontainers/cli@^0.79 features publish --registry ghcr.io/denisekart/open-facilitator/features features/src`. Publish tags the feature version (`:1.0.0`) plus the major tag (`:1`) — confirm the CLI's tagging with `features publish` docs/output; if the CLI only emits the full version, add an explicit `docker buildx imagetools create -t …/features/<name>:1 …/<name>:1.0.0` re-tag step per feature. Consumer coordinate: `ghcr.io/denisekart/open-facilitator/features/<name>:1`.
- **CI:** new `features` job in `ci.yml` (see Verification). No changes to existing jobs. `Makefile` gains `example-slim-up` (devcontainer-cli pointer + convenience) and adds `worker-e2e` to `.PHONY` (pre-existing wart, one-word fix).
