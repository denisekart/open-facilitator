## Context

Spec §12 (`docs/specs/open_facilitator_framework_architecture.md:632-677`) makes the Gateway owner of a typed allow/deny/confirm team policy over caller provenance, actor, operation, resource, and approval requirements. Today `src/gateway/src/policy.ts` is the Plan-05 seam: binary allow/deny, no actor/resource awareness, `DefaultPolicy` rules hardcoded. Plan 11 froze the kernel side of approvals (record/respond/lazy-expire/revoke, single-use law, digest verification) but deliberately left two holes labeled "Plan 12's hook": `IApprovalLedger.ConsumeAsync` (`src/facilitator/Kernel/Shared/Persistence/ApprovalLedger.cs:106-107,334`) has **no wire surface**, and the kernel **never pushes approval state to the Gateway** (no `approval.*` outbox producer exists). This plan lands the kernel wire delta (decided-push + Link consume command) and replaces the policy-seam guts with the §12 engine plus the Gateway-side confirm lifecycle, closing Phase C (§26.1 items 5+8).

## Locked decisions (planning-approved; deviations need a recorded reason in the commit message)

- **Round-trip mechanism (approved): push + Link consume command.** Kernel pushes a new event `org.facilitator.event.approval.decided.v1` to the originating Gateway over the existing Deliver machinery; Gateway atomically consumes via a new command `org.facilitator.command.approval.consume.v1` sent on `POST /api/link/v1/events`. No polling, no new REST surface, no new frame kind. Roadmap grants "one additive amendment per plan if a frozen schema proves short" (`IMPLEMENTATION_ROADMAP_PLAN.md:131`); this plan uses it for exactly these two additive schemas + one additive event.
- **Digest law (corrects the old draft):** the **Gateway computes** the canonical `actionDigest` via the already-exported `computeActionDigest` from `@ofac/protocol` (`src/protocol/src/digest.ts`, input record `{approvalId, action, eligibleActors, expiresAt, createdAt}`, nonce excluded — law D2, mirror of `Kernel/Shared/ApprovalDigest.cs`); the kernel recomputes-and-compares on ingest (`422 approval-digest-mismatch`). The kernel never computes the digest itself (spec §12.1 step 2).
- **Wire field names** are exactly `actionDigest`, `eligibleActors`, `nonce`, `expiresAt`, `createdAt` (+ optional 1.1 `action`, `workId`) per `protocol/json-schema/event.approval.required.v1.json`. There is no `approvers` field.
- **Policy DSL:** YAML mirroring spec §12's example (`:637-659`): top-level `owner`, `policies[]` of `{capability, resources[], actorAnyOf[], effect: allow|deny|confirm, conditions?}`. First-match-wins over the ordered list; implicit final **deny**. `conditions` are opaque key-values passed through to connectors, never evaluated by the engine (no condition mini-language). `resources` matched against a resource id derived from the assign command (§"Resource derivation" below). Policy revision = sha256 of the canonical file bytes, cited as `policyId = <owner>/<sha256-12>` in every audit line (§12.2 "policy ID/revision"); loading from a protected path is operator guidance, documented not enforced.
- **Schema home:** `protocol/json-schema/policy-file.v1.json` published in the contract tree for third-party gateway builders, but it is a **Gateway-local artifact**: not registered in the wire-envelope fixture dispatch classes; validated by the Gateway loader with Ajv-style structural checks already used by `@ofac/protocol`'s validator (`src/protocol/src/validate.ts` pattern — reuse `validateAgainstSchemaId` if it accepts non-envelope `$id`s; otherwise hand-rolled typed checks in the loader, no new dependency).
- **No policy file ⇒ current `DefaultPolicy` behavior + one boot warning** (capability-advertence rules unchanged, existing e2e tiers clean-cutover). The warning emits from `GatewayRuntime.start()` via `this.logger.warn` — `parseConfig` has no logger (fail-loud only).
- **Actor claims source order:** verified evidence subject + groups (from the command's `data.actorEvidenceRef`, §"Actor claims") > workload identity. Unverified evidence ⇒ workload only; deny any row with `actorAnyOf` (no privilege from untrusted fields, matching kernel law).
- **Pending state = ledger side table, not a `bindings` CHECK widen** (the CHECK at `src/gateway/src/ledger.ts:31` enumerates 4 states; SQLite CHECK needs a table rebuild, and `reconcile`/`probeChild`/quota-count read `running`, so a disguised-pending row would be reported `lost` on restart). New table `pending_actions` keyed by `approvalId`, in the same SQLite file, schema version 3.
- **Worker proof:** deterministic worker gains `research.publish`; the harness stays policy-agnostic (policy is Gateway-side, never child-side).
- **E2E approver:** realm user `alice` (password `alice`, `framework-admin`, group `/teams/team-alpha`) via password grant on the `facilitator-api` public client (`reference/keycloak/realm.json:46-52,260-276`).
