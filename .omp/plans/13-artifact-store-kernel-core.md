## Objective

Make the kernel the artifact authority (spec §15.4, appendix §8): a durable `facilitator.artifacts` metadata ledger + an `IArtifactStore` port (`Put/Get/List/Delete/VerifyDigest`) with a content-addressed filesystem adapter, an upload admission flow (`command.artifact.request-upload` over Link + a REST twin for humans/Gateway-relayed workers), digest verification at ingest (SHA-256 of received bytes must equal the declared digest), and real handling of the already-frozen `event.artifact.available` — recorded, same-tx audit + outbox-linked, visible on the Work timeline. After this plan bytes uploaded through the kernel survive worker destruction and are retrievable by `artifactId` with authorization; S3 backends, signed URLs, and `artifact://` resolution are the next plans' scope (§26.1 item 12 basis: digest verification, non-code media type, authorized download — the external-URL/SSRF half is Plan 14's).

## Expected state after

- `facilitator.artifacts` table (new migration `AddArtifactStore`): columns `artifact_id` (PK, uuid), `work_id`/`assignment_id` (nullable uuid), `media_type`, `size` (bigint), `digest` (`sha256:[0-9a-f]{64}`), `storage_uri`, `state` (`pending|stored|rejected|deleted`), `verification` (`verified|unverified`), `origin` (`link|rest|external`), `created_by`, `requested_by_endpoint_id` (nullable), `created_at`, `stored_at`, `retention_policy` (default `permanent`). Same-transaction audit rows (`AuditWriter.Append`) for allocation, store, reject, and external registration.
- `Kernel/Shared/Storage/IArtifactStore` port + `FileSystemArtifactStore` (config `Storage:FileSystem:RootPath`, content-addressed `{root}/{digest-hex[0..2]}/{digest-hex}` so dedupe is free); the store NEVER names S3/SeaweedFS.
- Link inbound arm `command.artifact.request-upload` (new schema, all three registration touchpoints) + REST twin `POST /api/artifacts/request-upload`: admission-screened, allocates a `pending` artifact row, and returns the ticket `{artifactId, uploadLocation, expiresAt}` **in-band**: `EnvelopeAck` and the HTTP `202` admission body gain an additive optional `data` field (see D1).
- Byte push: `PUT /api/artifacts/{id}/content` (human plane, OIDC + `artifacts.write`) and `PUT /api/link/v1/artifacts/{id}/content` (workload plane, link token, ownership-gated): kernel streams to store, recomputes SHA-256, mismatch ⇒ 422 typed `artifact-digest-mismatch` + row `rejected`; match ⇒ row `stored`, `verified`.
- `event.artifact.available` stops being a fall-through no-op: an `ArtifactIngress` arm in BOTH ingresses records the artifact row (kernel-stored rows are idempotently marked seen/stored; externally-declared `storageUrl` registers `unverified`), links `workId`, emits a timeline entry. The kernel-stored PUT itself also records + emits the timeline (the event arm never *requires* a preceding event for kernel-stored bytes — see D3).
- `GET /api/artifacts/{id}` (metadata) and `GET /api/artifacts/{id}/content` (bytes, FS-served) behind new gate bindings `artifacts.read`/`artifacts.write`; cross-team read ⇒ 404 (non-disclosure, mirroring the approvals work-scope 404 precedent).
- No `Storage:S3:*` keys, no presigned URLs, no `artifact://` resolver yet — those are Plan 14; the `file://` worker interim (`src/adapters/harnesses/deterministic/src/harness.ts`) stays untouched here.

## Locked decisions

- **D1 — Upload ticket in-band on the ack (additive, both planes):** `EnvelopeAck` (C# `LinkDtos.cs:74` + TS `core/types.ts:79-83` + the HTTP 202 body in `LinkAdmission.ToResult`) gains an optional `data` object. For a successfully admitted `command.artifact.request_upload`, the ack/202 body carries `data: {artifactId, uploadLocation, expiresAt}`. `uploadLocation` is a kernel-relative URL path (`/api/link/v1/artifacts/{id}/content` for Link-originated tickets, `/api/artifacts/{id}/content` for REST-originated), so the producer composes it against the base URL it already talks to and authenticates with the token it already holds — the Link-plane upload endpoint lives UNDER `/api/link/v1` precisely so `LinkAuthMiddleware` (guards `/api/link/v1` only) and the role-gate skip (`/api/link/v1*`) both already classify it: zero middleware change, workload-plane auth for free. Rationale vs alternatives: a kernel-pushed ticket event needs a NEW outbound event schema + a consumer nobody has yet; a deterministic-out-of-commandId scheme breaks the Link happy path. Kernel-side proxying is the honest FS backend — "signed URL direct to object store" arrives with Plan 14's S3 backend at the same response slot (additive amendment there), not as a fake here. Link NEVER carries artifact bytes inline (appendix §8.1): the upload is plain HTTP to the kernel, not an envelope.
- **D2 — Digest verified at the kernel boundary**, not at the Gateway ("artifact digests are checked here, not at the Gateway", `adapter.v1.json:203` law stays). Single algorithm SHA-256; digest regex from the frozen schema `^sha256:[0-9a-f]{64}$`. The kernel hashes the stream it receives (no client-hashed-trust shortcut) and additionally rejects a body whose actual size ≠ the allocation-declared `size` ⇒ 422 `artifact-size-mismatch` (same `rejected` row path as digest mismatch; a lying declaration must not smuggle unbounded bytes).
- **D3 — Two write paths, one ledger:** (a) kernel-stored: allocation → PUT bytes → row `stored`, `verification=verified`, `storageUri = "kernel-fs:" + relative-path`, timeline entry on store. (b) external registration via `event.artifact.available` carrying a client-supplied `storageUrl`: row `stored`, `verification=unverified`, no fetch (SSRF/verified-external rules are Plan 14's). The event arm on a kernel-stored `artifactId` is an idempotent no-op + timeline note (never re-writes mediaType/digest — first writer owns the row; mismatched re-declaration audited `deny` `artifact-reregistration-denied`). PUT-before-event works: the store path itself records + timeline-entries, so `artifact.available` is confirmation, not creation, for kernel-stored bytes. `additionalProperties: false` on the frozen event means no new fields ride it; anything extra is a row column, not a wire field.
- **D4 — Authorization:** team-scoped by `created_by`'s team. Workload plane: `LinkPrincipal.TeamSlug`/`requested_by_endpoint_id` ownership — an upload PUT for a foreign-team artifact ⇒ 404 (approval-consume ownership-404 precedent, `ApprovalLedger.cs:369-376`). Human plane: OIDC groups contain the artifact's team group (`/teams/<slug>` form, same group law as approvals) or the principal holds `framework-admin`; else 404 (non-disclosure). New bindings `artifacts.read` (GET `/api/artifacts/{id}`, `/api/artifacts/{id}/content`) / `artifacts.write` (POST `/api/artifacts/request-upload`, PUT `/api/artifacts/{id}/content`), `rolesAnyOf` mirroring `approvals.read`/`approvals.respond`. `PUT /api/link/v1/artifacts/{id}/content` is workload-authed, not role-gated (gate skips `/api/link/v1*`) — its guard is team/endpoint ownership in the handler.
- **D5 — No GC, no retention enforcement yet:** `retention_policy` column ships with `permanent` default so Plan 14's GC (S3 lifecycle) has its hook; no background janitor in this plan.
- **D6 — Command name literal:** schema file `command.artifact.request_upload.v1.json`, type `org.facilitator.command.artifact.request_upload.v1` (underscore — envelope pattern forbids hyphens, Known fact 3). REST route keeps the hyphen (`POST /api/artifacts/request-upload`); routes are unconstrained by the type pattern.
- **Split judgment:** kept as ONE plan — table+store+admission+verification+event-arm is one vertical; a store without an arm has no producer, an arm without a store has nowhere to point. Commit boundaries: (13a) wire delta + persistence + store + ledger, (13b) surfaces + arms, (13c) tests + docs; each a separate commit on `main`, status table updated per commit.

## Assumptions & contingencies

- **`artifactRef` seven-required-field mismatch:** frozen `artifactRef` requires `storageUrl`; kernel-FS artifacts' canonical `storageUrl` when Plan 15 embeds a ref is the absolute `GET /api/artifacts/{id}/content` URL. Nothing in THIS plan emits an `artifactRef`, so no amendment is needed here; if a Step-1 fixture review disagrees, the Plan 11 additive-amendment precedent applies (both harnesses same commit) — decide at Step 1, record in the status table.
- **Envelope payload cap vs upload admission:** `RequestBodies.MaxBodyBytes` is a compile-time 262144 const shared by all ingress bodies; the new command's payload is small, so no per-type limit machinery is needed. If a future envelope-classified artifact payload trips it, the fix is per-type limits, not a raised global cap — record which.
- **FS path traversal:** storage paths derive ONLY from the hex digest, never from client text; a client-controlled filename component is the bug class to avoid.
- **If `LinkAdmission` 4th-param renumbering breaks positional constructions**, convert them to named args mechanically — no compat shim.
- **Ack `data` on duplicates:** a duplicate `request_upload` re-attaches the stored ticket only while the row is `pending` and un-expired; expired/rejected ⇒ duplicate ack without `data` (producer re-requests with a fresh commandId). Do NOT mutate the row on duplicate.
- **Replanning caveat:** Plan 14's real S3 producer may show the ticket shape too thin (no signed-URL slot); `uploadLocation` + additive amendment in 14 absorbs that — not a re-do here.
