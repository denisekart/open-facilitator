## Context

Plan 13 shipped an artifact ledger whose byte plane proxies everything through the kernel: upload admission returns a **kernel-relative** `uploadLocation`, callers `PUT` bytes through the kernel which hashes them on arrival, and `GET {id}/content` streams from the local filesystem. The production-shaped design (spec 15.4, appendix 8.2) requires presigned PUT/GET so large bytes bypass the kernel, an SSRF-screened admission for external references, and a retention GC pass. This plan delivers all three against an S3-compatible endpoint (reference target SeaweedFS `weed`, pinned `SEAWEEDFS_TAG=4.48` in `reference/versions.env`, Testcontainers-only — no compose files exist yet; the reference Compose env is a later plan). Clean cutover law: FS remains the dev/test default selected by config — no dual-write, no shim; the request-upload response gains a real signed-URL slot, and every provider stores under the SAME content-addressed key so a row can migrate providers by re-pointing the scheme.

## Expected state after

- `S3ArtifactStore : IArtifactStore` selected by `Storage:Provider` (`filesystem|s3`), read once at startup; new `Storage:S3` config block (endpoint, bucket, region, accessKey, secretKey, forcePathStyle).
- Object keys are **digest-derived and identical across providers**: `{sha256-hex[0..2]}/{sha256-hex}` (the FS store's `RelativePathOf` law reused verbatim). Content stays addressable independent of backend.
- The upload ticket response becomes `{artifactId, uploadLocation, uploadUrl?, method, expiresAt}` on every surface that emits a ticket (REST 201, link ack `data`, duplicate re-attach). `uploadUrl`/`method:"PUT"` present only when the store can hand out a direct signed URL (s3 provider; pending row); `filesystem` keeps `method:"POST"` + `uploadLocation` (kernel-proxied PUT). Callers use `uploadUrl` when present, else `uploadLocation`.
- Two confirmation paths, both landing `pending -> stored` through the SAME ledger verification: (a) proxied PUT — unchanged for FS/small human uploads; (b) **confirm** — `POST /api/artifacts/{id}/confirm` (REST + link plane): kernel HEADs the object at the digest key, checks declared size, GETs and re-hashes to verify the declared sha256 (S3 ETags are md5, never sha256 — the kernel NEVER trusts an ETag as the digest).
- `GET /api/artifacts/{id}/content` for kernel-hosted rows becomes a **302 to a presigned GET** (s3 provider) / remains a stream (filesystem). The kernel keeps the authz decision; only the byte hop moves.
- Verified-external admission (spec 15.4 bullet 3, tightened): an `event.artifact.available` carrying an http(s) `storageUrl` is screened against operator bindings (`Storage:ExternalBindings`: id, urlPrefix) + SSRF rules (DNS-resolve once; reject any resolved address in private/loopback/link-local/multicast/reserved ranges **unless an operator binding names it**). Outcome recorded in the existing `verification` column: bound+clean -> `verified`, otherwise `external:<url>` + `unverified` (today's behavior for unbound). `external:`-scheme `storageUrl` registers `unverified`, never screened (no fetch implied). The kernel NEVER fetches external bytes.
- Retention GC: serialized background pass honoring `permanent`, `Nd` (age-based delete of unreferenced rows), and `archive` (never deleted; deferred to storage-tiering — the kernel-side semantics locked below). Reference check + expiry + tombstone in one short transaction, backend delete after commit, audit + `artifact.gc` timeline, idempotent and restart-safe.
- The whole existing artifact suite runs against **both providers** via a test matrix (shared base classes, fs and s3 collection classes); the s3 leg rides a SeaweedFS Testcontainer mirroring the pinned tag.
- GC also sweeps **expired unclaimed slots** (`pending` rows past `ExpiresAt`): `pending -> deleted`, audit, no backend call (never stored). Fills the deferral row in docs/security.md.
- Wire amendment (additive, one commit): `command.artifact.request_upload.v1.json` `retentionPolicy` enum widens to `["permanent","archive"]` plus a pattern-validated `Nd` branch (schema shape locked in Step 3), new `command.artifact.confirm_upload.v1.json`, both-harness fixtures, codegen, drift-clean.

## Locked decisions

- **D1 — One port, two adapters, config-selected.** `Storage:Provider` read once at startup (existing switch); runtime flip requires restart. FS stays the zero-dependency default so the default test tiers gain no new container. `S3ArtifactStore` constructor fails closed on blank endpoint/bucket/credentials (FS-precedent message style).
- **D2 — Digest-derived keys are provider-law.** Every adapter stores at `{digest[..2]}/{digest}`. Consequences: presigned PUT targets a key the kernel computed BEFORE the bytes exist (the client declared the digest at admission); content dedupe, provider migration, and the GC's ability to address any object all fall out for free. A presigned URL is minted only for a key already fixed by the admission — never a caller-supplied key.
- **D3 — Presigned URL surface.** `PresignUploadAsync(relativePath, ttl, ct) -> Uri?` and `PresignDownloadAsync(relativePath, ttl, ct) -> Uri?` are **optional capabilities** declared on a new `IStoreSignedUrlSource` interface (implemented by S3 only, no change to `IArtifactStore`); the ledger/endpoints probe with `is IStoreSignedUrlSource`. FS returns no `uploadUrl` and keeps streaming. TTL reuses `AllocationTtl` (15 min) so ticket expiry and URL expiry are ONE timestamp — no new field semantics. The URL lives only in the ticket response; the row keeps the canonical `s3://bucket/{key}` URI (scheme law below). No bucket-level or writable-prefix URLs (appendix 8.1: no long-lived bearer secrets; the URL never rides a manifest).
- **D4 — StorageUri scheme = adapter-supplied.** New port member `string StorageUriScheme { get; }` (FS: `"kernel-fs"`, S3: `"s3"`); ledger's StoreAsync/confirm replace `"kernel-fs:"+relpath` with `store.StorageUriScheme + ":" + put.RelativePath`, and `GetReadableAsync`'s filter becomes `IsKernelHosted(view.StorageUri)` = scheme of one of the configured adapters (simplification chosen over a hardcoded two-scheme list: one method on the store, `Owns(uri)` — see Step 2). `ArtifactEndpoints.cs:97`'s prefix slice likewise asks the store for the key back.
- **D5 — Confirm = kernel re-hash, no ETag trust.** SeaweedFS (and S3 multipart) ETags are md5/composite — never sha256. The confirm path: HEAD (must exist, `ContentLength == declared size`, else 422 `artifact-size-mismatch` + reject) -> GET + incremental SHA-256 (`VerifyDigestAsync`-equivalent re-hash) -> mismatch 422 `artifact-digest-mismatch` + reject. Same code path as proxied PUT's post-put check: extract a shared `ConfirmStoredAsync(artifactId, digestHex, size, ...)` in the ledger used by BOTH the proxied PUT handler and the confirm endpoint, so both planes share the conditional-update + audit + timeline + metrics law. Byte re-read on confirm is accepted cost; first-read caching is out of scope.
- **D6 — External screen keeps `external:` scheme.** The original plan's "row records `external` + binding id" is DROPPED as a needless schema change: the `verification` column (`verified|unverified`, CHECK-constrained) already carries the outcome — a bound, SSRF-clean external ref stores `external:<url>` with `verification="verified"`; everything else is exactly today's `unverified`. Non-URL evidence (binding ids, screens) rides the audit record (`artifact.registered` details), not a column. Binding table = config `Storage:ExternalBindings`: `[{ "Id": "...", "UrlPrefix": "https://..." }]` (prefix match, exact host from the prefix). SSRF screen: scheme http(s), no userinfo, host resolves (via `Dns.GetHostAddressesAsync`) and EVERY address must be outside `IsPrivate/IsLoopback/IsLinkLocalUnicast/IsLinkLocalMulticast/IsMulticast/IPv6UniqueLocal/6to4` and `0.0.0.0/8` (mirrors `System.Net.IPAddress` helpers + explicit blocks; no new dependency); a binding's `UrlPrefix` match waives the address screen only (scheme/userinfo always apply). Default-deny: unbound private-address URL -> `unverified`. The kernel NEVER fetches. `external:`-scheme `storageUrl` values skip the screen (they assert no fetchability).
- **D7 — GC correctness over cleverness.** Serialized pass via `pg_advisory_lock` (new fixed key 420002, migration-lock precedent cited), single `RetentionGcService : BackgroundService` copying `OutboxDispatcher`'s loop shape (interval-minted via `TimeProvider`, try/catch log-and-continue). Per candidate: short transaction opens with `SELECT ... FOR UPDATE` on the row, evaluate retention + reference check, conditional update to `deleted` + audit in-tx; commit; backend `DeleteAsync` after commit (idempotent). Restart between delete and tombstone: row `stored` still, re-collected next pass. No distributed scheduling.
- **D8 — Retention semantics (spec names `archive` but never defines it; locked here):**
  - `permanent` — never collected by age.
  - `Nd` (N >= 1, e.g. `30d`) — eligible when `stored_at + Nd < now` AND unreferenced (reference check: row's `work_id` is NULL or that Work is terminal per `StateGuard.IsTerminal`; Plan 15's manifests reference `artifactUri` inside documents with no artifactId-keyed index, so no manifest join exists in either merge order).
  - `archive` — NEVER deleted by this GC, eligible for nothing yet: audit-documented kernel-side tombstone-free hold; storage-tiering to cold layer is a future ops concern. GC counts archived-skips in the pass metric only.
  - Wire widening: `retentionPolicy` accepts `"permanent"`, `"archive"`, or `Nd` (pattern `^[1-9][0-9]{0,3}d$`). One schema, no enum for the numeric family: `"anyOf": [ {"enum":["permanent","archive"]}, {"type":"string","pattern":"^[1-9][0-9]{0,3}d$"} ]`. `ArtifactArmPolicy.TryParse` mirrors exactly this grammar; store it verbatim on the row (already `text`, no CHECK on the column today — no migration).
  - **Expired unclaimed slots:** `pending` past `ExpiresAt` -> `deleted` + audit `artifact.gc` + timeline note when `work_id` set; no backend delete (bytes never arrived); metric-tagged `reason=expired-slot`.
  - Batch cap 100 rows/pass, ordered by `artifact_id` (determinism), loop resumes next tick.
- **D9 — Confirm is a wire command.** New `command.artifact.confirm_upload.v1.json`: `{commandId (required), artifactId (required, idToken), comment?}` — `additionalProperties:false`, same `$id`/title conventions; handler in `ArtifactIngress` rides the existing admission/evidence plane (the command already carries the link principal; no `actorEvidenceRef` needed — the link token IS the actor proof, matching request_upload's own handling where evidence was already admitted upstream). REST twin `POST /api/artifacts/{id}/confirm` (role `artifacts.write`). Handler: row must be `pending` AND s3-hosted (`s3:` scheme after re-point — see D10); non-pending -> 404-style problem `artifact-not-found` for foreign teams, `artifact-not-pending` (new ProblemErrors entry, 409) for same-team non-pending. Fixtures: `valid/command.artifact.confirm-upload.json` + one invalid (missing artifactId); `index.json` entry; both harnesses same commit.
- **D10 — Provider switch by scheme, single-source rule.** Once a row is `stored`, its scheme decides every later read/download/confirm/GC action — nothing re-reads `Storage:Provider` for existing rows. A dev kernel switching providers between runs leaves foreign-scheme rows readable-but-inert (`GetReadableAsync` returns null for a scheme no configured adapter `Owns`), acceptable for dev. The s3 test-collection leg therefore seeds its own rows; no cross-provider fixture reuse.
- **D11 — Metrics.** Counters on the existing meter: `facilitator.artifact.confirmed` (tags: `origin`), `facilitator.artifact.presigned` (tag: `op=upload|download`), `facilitator.artifact.gc.collected` (tag: `reason=retention|expired-slot`), `facilitator.artifact.store.errors` (tag: `op`), observable gauge `facilitator.artifact.gc.last_pass_age`. Typed methods on `KernelMetrics.cs`. The skill's observability inventory updates same change.
- **D12 — No new Testcontainers package.** Generic `ContainerBuilder` + the pinned tag literal `"docker.io/chrislusf/seaweedfs:4.48"` (mirrors Postgres/Keycloak fixture precedent of hard-coded literals; CI `meta` job already guards the versions.env key). CPM adds exactly one entry: `AWSSDK.S3` (4.x line — 4.0.104 current as of 2026-07; take latest 4.x at Step 0).
- **Split judgment:** ONE plan. Adapter, presign/confirm, external screen, and GC share the ledger's state machine and the ticket surface; splitting ships an un-collectable, half-cut-over store. Commit-boundary order for reviewability: (1) port extension + S3 adapter + config + matrix green on FS-regression, (2) ticket/confirm/302 cutover + wire amendment, (3) external screen + GC, (4) tests/docs. Each commit keeps `make build && make test` green.
