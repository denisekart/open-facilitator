## Context

Today a worker completes an Assignment by publishing `org.facilitator.event.assignment.completed.v1` with a small **inline** `data.resultManifest` whose single output's `storageUrl` is a local `file://` URL; the kernel stores the envelope in the inbox and records **nothing** from it — no manifest row, no timeline entry, no artifact linkage. Spec §15.3 and appendix §8.3 make the completion truth an **immutable Result Manifest**: a canonical-JSON document, stored as an artifact, referenced from the completed event by `resultManifestRef` + `resultDigest` (RFC 8785 digest), with corrections creating linked revisions. This plan makes that real end-to-end: the wire amendment, the kernel recorder + GET surface, the `@ofac/adapter` artifact client so third-party harnesses get the capability without touching wire details, and the deterministic worker's cutover — the Phase G adoption thesis earning its keep early.

**Amendment decision (settled, no longer open):** the completed-event **amendment** wins over a sibling `event.result.recorded` — spec §15.3's own example extends the completed event, and the `adapter.v1.json` if/then `$ref`s the payload schema by filename, so a data-field change re-touches only the payload schema + fixtures + DTOs, not the relay frame. Corrections ride the **same completed-event path** (a second completed event with ref+digest for the same Assignment chains revision N+1); **no new command type** — a `command.result.record_manifest` would have zero in-plan consumers (admin re-marking is the admin-surface plan's). The inline `data.resultManifest` stays **required in the 1.0 schema** (no breaking change) but becomes deprecated-in-fact: when `resultManifestRef` is present the kernel ignores the inline document; when it is absent (legacy producers), the kernel records nothing extra — exactly today's behavior.

```csharp
Task<ResultManifestOutcome> RecordAsync(JsonElement manifestDoc, Guid manifestArtifactId,
    string wireDigest, Guid workId, Guid assignmentId, string executionId,
    EffectivePrincipal? principal, CancellationToken ct)
```

One tx, ApprovalLedger shape:
1. **Verify bytes:** load artifact row by `manifestArtifactId` (must exist, `verified` state, team = work's team); stream from `IArtifactStore`; parse as JSON. Missing/foreign artifact ⇒ `ArtifactMissing` outcome.
2. **Verify canonical form + digest:** recompute the canonical digest of the **received bytes as-stored** — re-serialize via the same normalize (JsonElement→CLR, NFC, ints→double) + `Jcs.Net` canonicalize + SHA-256 as `ApprovalDigest` — compare to `wireDigest` (422 on mismatch, `metrics.ManifestDigestMismatch()`) **and** require the stored bytes to equal the canonical form byte-for-byte (the assumption that builder-emitted == golden-canonical is enforced, not assumed: a non-canonical submission is rejected, digest of what was actually stored is the record). The doc's own `manifestId` must equal the wire/entity id; `digest`/`artifactId` fields inside the doc are informational.
3. **Chain:** look up the current non-superseded row for `assignmentId` (lock via `SELECT … FOR UPDATE` on the latest row); none ⇒ `revision = 1`, `revision_of = NULL`; else `revision = current+1`, `revision_of = current.manifest_id`, and in the same tx flip the old row `state = 'superseded'`, `result_state = 'superseded'` (conditional UPDATE, race loser re-reads → returns `Duplicate` on identical re-delivery of the same wire envelope via the inbox anyway).
4. **Cross-check the document:** every `outputs[].artifactId` parses as a GUID **and** resolves to a verified, same-team artifact row whose stored digest equals the doc's declared `digest` (the four-output-classes verification hook; external refs are opaque pointers — recorded, never fetched, §15.4's SSRF law: the kernel never dereferences them). One mismatch ⇒ 422, no rows.
5. Insert row (`result_state='available'`, `state='recorded'`, `structured_digest` = SHA-256 over the canonicalized `structuredResult` sub-document when present); `audit.Append(db, …)` action `manifest.recorded`; timeline `WorkEventEntity` Kind `manifest.recorded`, Detail `{manifestId, revision, digest}`; outbox push envelope `org.facilitator.event.result.manifest.recorded.v1`? **No new event type** — reuse the approvals outbox envelope law with a plain audit-only decision: skip outbox; the timeline + row are the record (GET surface is pull). `SaveChanges` + commit + `PostgresNotifications.NotifyOutboxAsync` stays for tx hygiene only if outbox rows exist (they don't) — keep the calls consistent with `ArtifactLedger.ConfirmStoredAsync`'s tail minus the outbox add.

- **Artifact-URI resolution is last-path-segment = artifact GUID**, the client builder being the only first-party emitter of `artifact://` URIs. If during Step 2 a URN-ish idToken scheme instead fits the validators better, keep the wire field as-is (it is a `format: uri` string) and adapt the resolver — the law, not the field, may move; record it.
