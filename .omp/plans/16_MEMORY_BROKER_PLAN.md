## Objective

Make the kernel a memory broker (spec §14.3 core ops, appendix §6): Postgres-backed entries with scope ownership + ACL-before-search, the frozen `memory.candidate` lifecycle (candidate → promote → active, §14.6), full-text `recall` with provenance metadata, the `memory.used` usage-event law on every automated read (§6.2), per-Project-aware retention, the cross-team private block, and audit on every op (§14.9). `@ofac/adapter` grows a memory client on the artifact-client pattern. ## Locked decisions

- **D1 — Synchronous retain, no queue.** Retain commits the entry in-transaction and returns a receipt in-band (REST 201 / ack `data`); §14.6's async-queue messaging is deferred — the FTS provider has no extraction/embedding cost, a queue would be theater. `memory.retained|rejected` event schemas are NOT added (fewer frozen surfaces). If a later provider needs async, it lands additively.
- **D2 — ACL before search, always.** Recall resolves the caller's readable-scope predicate first and embeds it in the SQL `WHERE` (never post-filters). The predicate: `status <> 'tombstoned' AND (team_slug = :callerTeam OR policy_label = 'facilitator-visible' OR EXISTS share to :callerTeam)`, PLUS caller-team-private rule: `policy_label = 'private'` rows match ONLY on `team_slug = :callerTeam` or a share — never via a different team's `facilitator-visible` (the label is the OWNER team's publication intent; private can't be public by construction). `policy_label = 'evidence-only'` rows are recalled with `content` replaced by `contentSummary` (metadata visible to those who can see them, full text via evidence). Denial discloses nothing: no count, no "N hidden", scoped error only.
- **D3 — `memory.used` on every automated read that returns entries.** The broker's recall path writes one `memory_usage` row per returned entry (consumer = caller actor, purpose from the request, justification = recall `purpose` + query prefix) inside the recall transaction, plus audit `memory.used`. External read-then-decide consumers attest via the frozen `event.memory.used` envelope (arm records the same rows). Kernel-internal consumers arrive with later decision-provider work and write the same rows — do NOT fabricate an internal reader now.
- **D4 — Link-plane writes land `candidate` + `team-only` default.** A workload `command.memory.retain` or an `event.memory.candidate` always lands `status='candidate'`; the frozen optional `policyLabel` is honored but may only NARROW (`facilitator-visible` from an external candidate is honored as-is only when the owning team's config permits — v1 law: honor the label verbatim, it can never exceed `team-only` reach for private teams since `facilitator-visible` is the widest shareless label). REST human retain lands `status='active'` (an owner writing deliberately). A workload cannot promote/correct/delete — curation ops are REST-plane (`memory.curate` binding).
- **D5 — Deletion law:** tombstone + content drop + share revocation + usage-row retention in ONE tx; physical content dropped at tombstone (row keeps `content_hash` + metadata for audit); FTS row excluded from every query by the status predicate (the tsvector computed column over emptied content recomputes — no trigger plumbing). Backup-retention honesty stays docs prose (§14.6).
- **D6 — Scope rows are provisioned lazily by retain** (owner team + selector), no bootstrap fan-out. `memory_scopes.kind` ∈ `work|project|team|private`; frozen-enum mapping per Known fact 2.
- **D7 — Per-Project retention home:** `projects.config` jsonb key `"memory"` → `{"workCandidateDays": int, "candidateDays": int}` (matches §14.11 `memory.yaml` `retention.*` names), read at retain time when the target scope resolves through a project (work/project scopes); fallback `Memory:Retention:CandidateDays` config default 90. No new policy table — Plan 14 precedent, `projects.config` is the as-built per-Project carrier.
- **D8 — Recall response shape = §14.11 verbatim:** `{requestId, providerProfile:"postgres-fts", entries[], truncated, asOf}`; entry DTO: `entryId, scopeId, type, content, contentHash, provenance, observedAt, effectiveFrom, revision, status, policyLabel, retrievalReason` (retrievalReason = `"fts-rank <score>"` string + `match` flag). `maxItems` default 8 max 20; `maxTokens` heuristic = chars/4, drops whole entries tail-first, never splits one.
- **D9 — Quota/payload guards (§14.8 #3):** `Memory:Quota:MaxContentChars` 16384 (REST body + schema `maxLength`), `Memory:Quota:DailyRetainPerTeam` 200 (count of today's UTC rows for the team ⇒ 422 `memory-quota-exceeded`, audit deny); duplicate detection = content-hash dedupe NOTE only: a same-team same-hash retain within the scope returns the existing `entryId` + `duplicate: true` in the receipt (no new row) — dedupe, not rejection.
- **D10 — No kernel `reflect` endpoint** (no consumer; adapter returns typed `unsupported`), **no import** (export only), **no consolidation**. Provider port `IMemoryProvider` ships as the seam with `PostgresFtsMemoryProvider` as its only implementation; the Hindsight adapter is a documented non-implementation (§14.7), NOT an empty class — the broker calls the port, and only the port.
