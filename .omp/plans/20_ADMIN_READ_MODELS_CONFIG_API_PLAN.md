# Plan 20 — Admin surface, leg 1: kernel admin read models and configuration API

**Status:** 🔵 replanned (this content replaces `.omp/plans/20-admin-read-models-config-api.md` verbatim on approval; flips 🟡 when implementation starts)
**Depends on:** 19 as-built (`19_SLIM_ACCEPTANCE_VERIFY_CI_PLAN.md`: compose stack, `referencectl`, `reference/checks/verify.sh` all exist). **Phase E leg 4 of 5.** Operator-surface chain: 20 → 21.

## Objective
Build the server half of spec §17: the `/api/admin/*` read/write surface the embedded inspector (Plan 21) consumes — universal search, health summary, object detail + timeline, link/delivery state with dead-letter **replay**, inline metrics roll-up, and `PATCH /api/admin/config/{resource}` with true `If-Match` optimistic revision (§17.4). Read models query the existing Postgres ledgers; the API is the only new truth-teller, never a second store. Dev affordances (`/api/dev/*`) cut over to admin equivalents, not kept alongside. Kernel-only change: no gateway/workspace-link/SDK code, no new npm or NuGet packages.

## Locked decisions
- **Inspector-first scope:** all §17.4 GET read models + dead-letter replay POST + manifest re-mark POST + config `PATCH` land here. §17.3 editable-field classes become config **resources** with validation + audit but **persist-only semantics** — no kernel behavior reads them yet (decision: behavior read-through lands per-feature when a consumer exists; a `Config:`-file value remains the runtime truth; recorded so Plan 21's UI labels config as "stored intent" not "live toggle").
- **`If-Match` is a real header** on config PATCH: `ETag` on GET/PATCH responses = rowVersion; mismatch → **412 Precondition Failed**; missing `If-Match` → **428 Precondition Required**. Roles API keeps its body-rowVersion law untouched.
- Search is **SQL-bounded** (typed sections per entity, each `LIMIT`ed, `ILIKE '%q%'`, no new index/FTS until measurements demand); message-ID search matches outbox/inbox/dead-letter id columns as text.
- Config store copies the roles pattern: table `facilitator.admin_config`, same-tx audit + bounded per-resource history, rollback = PATCH to a prior payload.
- One authorization operation set: `admin.read` (GETs, `framework-admin`|`kernel-operator`) and `admin.mutate` (POST/PATCH, `framework-admin`|`kernel-operator`) in **both** config files. Rationale for including `kernel-operator`: the existing cli/service token must keep passing a smoke-style probe, and CI already authenticates with it.
- Clean cutover: `/api/dev/deliveries` and `/api/dev/link-outbox` and `GET /api/dead-letters` are **deleted**; every consumer moves to an admin route. No compat aliases.

### 3. Mutations
- `POST /api/admin/dead-letters/{deadLetterId:guid}/replay` → new `OutboxAdminStore.ReplayAsync(Guid deadLetterId, ct)` + `OutboxRepository.ReplayAsync`: load dead-letter row + source outbox row (404 `dead-letter-not-found`); re-validate envelope with `EnvelopeValidator` **fail-closed** (422 `replay-envelope-invalid`, envelope is never edited — appendix §17.2 "retry without editing the payload"); insert a NEW outbox row reusing `recipient_endpoint_id`, `aggregate_type/id`, `work_id`, `event_type`, envelope verbatim, fresh `outbox_id`, `commandId = "replay:" + deadLetterId` (deterministic → double-replay collides on `outbox_command_id_key`, caught → 409 `version-conflict` "already replayed"), `status=pending`, `available_at=now`, `attempts=0`; same-tx `AuditWriter.Append` (action `admin.dead-letter.replay`, resource `/api/admin/dead-letters/{id}`); `NotifyOutboxAsync` after commit (AppendAsync template). **Idempotency law unchanged: the ledger arbitrates, not the UI** — replay twice ⇒ one business command.
- `POST /api/admin/manifests/{manifestId}/re-mark?resultState=` — body `{ "resultState": "available"|"validated"|"rejected" }` (target only; `missing`/`superseded` are chain-law owned → 400 `manifest-re-mark-invalid`); UPDATE touches `result_state` ONLY (Plan 15 immutability law), 404 `manifest-not-found`, same-tx audit `admin.manifest.re-mark`; result-state transition table: none — any→any of the three writable states (decision: re-mark is a human attestation, not a machine chain).
- `PATCH /api/admin/config/{resource}` — handler: parse `If-Match` (`*` = force, else quoted int ETag); absence → 428 `config-precondition-missing`; store conflict → 412 `config-version-conflict` (ProblemDetails, re-read-and-retry detail like the roles 409); success → 200 + new `ETag` header + `{resource, payload, rowVersion, author, reason, updatedAt}` body + audit; reason REQUIRED (header `X-Change-Reason`, non-empty, ≤512 → 400 `config-invalid`), author = `http.GetFacilitatorPrincipal()?.Actor` (§17.1 attribution). `GET /api/admin/config/{resource}` → 200 + ETag + body; `GET /api/admin/config` → resource list w/ rowVersions (never 404s — empty list); `GET /api/admin/config/{resource}/history?limit=` (cap 20).
