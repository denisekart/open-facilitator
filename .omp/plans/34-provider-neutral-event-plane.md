## Context

Three sentences, each binding (locked user law, 2026-10-30):

1. **No unknown types.** Every message type crossing a seam is enumerable and schema-validated by the core protocol. A provider name is never a wire-type segment, a generated core type name, or a kernel string comparison.
2. **Domain-specific, provider-neutral, purpose-bearing events live in protocol + kernel.** The core vocabulary is integration DOMAINS (chat, issues, change requests, pipelines), not vendors.
3. **Adapters are the mapping layer.** Inbound: translate provider vocabularies into the central domain event that relays the PURPOSE. Outbound: translate that purpose into provider API instructions. Provider→purpose and purpose→provider mappings live nowhere else.

Adoption consequence: a new forge (GitLab, GitHub fast-follow) ships as **normalizer + connector policy + one `Providers:<name>` config section**. The core protocol changes only when a genuinely new domain or action purpose appears — an explicit enum widening, never a silent string.

## Locked design decisions

- **Central closed type set (6 types):**
  `org.facilitator.event.provider.message.v1` · `.mention.v1` · `.reaction.v1` (chat family — the Mattermost adapter's `mention/reaction/message` hook vocabulary becomes in-package mapping data, exactly like forgejo's `issues/pull_request/status`)
  `org.facilitator.event.provider.issue.v1`
  `org.facilitator.event.provider.change_request.v1` (word locked: `change_request`, forge-neutral — GitLab `merge_request` / GitHub `pull_request` map in)
  `org.facilitator.event.provider.pipeline.v1` (word locked: `pipeline`)
- **Provider is data, not type.** `data.provider` (required, `$ref common.v1.json#/$defs/idToken`) names the provider token (`forgejo`, `mattermost`); `reference.provider` MUST equal it (kernel cross-check, Step 2). Registry lookup, tenant gate, endpoint-speaker gate, and dedupe `(provider, provider_delivery_id)` all key off the data token. `ProviderEventClass`: prefix routing + closed 6-type membership + provider token read from envelope `data.provider`, never parsed from the type.
- **Action enums stay closed, per domain** (moved verbatim from the vendor schemas): issue `opened|labeled|commented|closed` (+ required `workTrigger` boolean); change_request `opened|synchronized|reopened|reviewed|commented|merged|closed`; pipeline `pending|success|failure|error`. Chat family keeps its shapes (mention/message required `text` 1..8192; reaction required `emojiName` 1..64). `workTrigger`, `text`, `description`, `payload` (verbatim provider body, `additionalProperties: true`) carry over per domain as today. All 6 schemas: `additionalProperties: false`, `required` includes `reference`, `provider`, `providerDeliveryId`, `actorProviderAccountId` plus the domain discriminators.
- **Sender binding law:** AdmissionGate requires the sending link endpoint's id (`workload.EndpointId`) == the resolved provider section's `EndpointId`, in addition to the section being enabled. Wrong-claimed provider token, `data.provider != reference.provider`, or wrong-speaker endpoint ⇒ typed `unsupported` (`ProblemErrors.Unsupported`) + failed audit row (existing fail-closed path).
- **Kernel arms switch on the 6 central types.** Behavior byte-identical to the as-committed arms: Work create + binding + interim assign on `issue.v1` `labeled`+`workTrigger`; input note on comments/pipeline verdicts; deferred steer on `change_request.v1` `reviewed` with judgment id `$"{provider}-review:{providerDeliveryId}"` (provider from data); echo law. Domain judgment strings (`steered:`, `observe:unbound`, `observe:unhandled`, `echo:post-ledger`, `link:challenged`, `mention:{id}:unlinked`, `reaction:audited:`) unchanged.
- **Kill every provider-name branch AND vendor prose in the kernel.** `ResolveBotIdAsync`'s `options.Provider != ProviderOptions.Mattermost` special case becomes config-driven: **`BotIdentityProbeUrl: string?`** (a deviation from the earlier `BotIdentityProbe: bool` sketch, justified: a bool still forces the Mattermost REST path `/api/v4/users/me` into kernel code, i.e. vendor API shape as kernel vocabulary — a full URL is pure config data). When set and `BotUserId` unset: GET it once with `Authorization: Bearer` from `BotToken`/`BotTokenFile`, parse root `.id`, cache (existing single-slot `resolvedBotId` + retry-next-event semantics unchanged). The `/link` unlinked-DM copy moves to the provider section as **`LinkHintText: string?`** (mattermost overlay carries the current string); when null, an unlinked mention is audited (`mention:{id}:unlinked`) but no reply command is appended — no text, no lie. `ProviderOptions.Mattermost`, `MattermostPrefix`, `SectionName="Providers:Mattermost"` constants die — the section name survives only as DATA (`Providers:mattermost`). The kernel keeps zero vendor vocabulary, including judgment prose (see Step 2 fallback-string rewording).
- **`Providers:<name>` sections keep** `Enabled/EndpointId/Tenant/SiteUrl/BotUserId/BotToken/BotTokenFile/AssignEndpointId/AssignCapabilityId/AssignTargetId` + the new `BotIdentityProbeUrl`/`LinkHintText`; section name lowercased = provider token; fail-closed per section unchanged (enabled + missing EndpointId/Tenant ⇒ `InvalidOperationException` at composition).
- **Dataschema URL:** `https://schemas.openfacilitator.org/v1/event.provider.<domain>.v1.json` per central schema (user-decided; matches the existing `/v1/` prefix and the `dataschemaFor()` law); fixture filenames + `index.json` rows follow.
- **Capability ids neutralize now** (user-decided): vendor-scoped connector ids are wire-visible team advertisements, so they follow the same domain vocabulary. Rename map (exact):
  | old                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                           | new                          |
  | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | ---------------------------- |
  | `forgejo.issue.read`                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                          | `vcs.issue.read`             |
  | `forgejo.issue.comment`                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                       | `vcs.issue.comment`          |
  | `forgejo.pr.create`                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                           | `vcs.change_request.create`  |
  | `forgejo.pr.comment`                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                          | `vcs.change_request.comment` |

  | `forgejo.ci.trigger`                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                          | `vcs.pipeline.trigger`       |
