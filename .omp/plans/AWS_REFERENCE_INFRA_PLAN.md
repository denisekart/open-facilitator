# AWS Reference Infrastructure (examples/aws) — Implementation Plan

## Context

Ship a presentable, fork-me AWS deployment reference for open-facilitator: CDK (TypeScript) stacks, one per workload, under a new pnpm workspace member `examples/aws/`, plus a docs guide **local to the package** (`examples/aws/README.md` — all AWS docs stay there, not in `docs/`). Two account classes: **platform** (kernel, data, identity) and **team** (gateway/workspaces/fleet launcher, outbound-only). Secure defaults: private subnets, no public IPs, Secrets Manager, task IAM roles, TLS, WAF only on the single web face (webhooks + link-plane enrollment/hub). Create-or-reference for company-owned things (VPC, DNS zone, IdP federation); always-create for local infra (RDS, S3, secrets, EFS). No AWS credentials exist anywhere during dev/CI: the gate is synth snapshots + cdk-nag + a local-only LocalStack smoke. `cdk deploy` appears in **no** live pipeline; the README documents the deploy approach instead. Non-goals: EKS, multi-region, Terraform, self-hosted forge stacks (we never ship platforms we interact with — GitLab.com SaaS is the README's example provider).

Decisions already made (do not re-litigate): one CDK app with per-stack `env` from a context file; RDS **serverless v2 only**; images referenced by digest-pinned URIs from context (ghcr today, any registry incl. GitLab later — no enum switch); identity = Cognito user pool with optional corporate-IdP federation props; infra-level auth (ALB forward-auth to Cognito on admin/SPA paths) **default ON**, skippable by prop, kernel app-level OIDC authz always underneath; autoscaling = CPU/memory target-tracking only, queue-depth (`facilitator.outbox.queue_depth`) documented via OTLP→CloudWatch with namespace confirmed at deploy time; observability = **ADOT collector sidecar** in a deletable stack; team state = EFS per team with access points; enrollment secret = documented manual cross-account hand-off (short-lived re-enroll is the rotation story); fleet launcher = **new non-production reference package** `examples/aws/fleet-launcher` (link-plane client, team account, dials the kernel, ECS RunTask on local static rules) — the kernel never calls it.

## Step 2 — Kernel S3 credential fallback (independent .NET change)

`src/facilitator/Kernel/Shared/Storage/S3ArtifactStore.cs` (ctor, lines ~28–75): today AccessKey/SecretKey are fail-closed-required and it builds `BasicAWSCredentials`. Change: keys become OPTIONAL as a pair — if both present, behavior byte-identical (SigV4 static, presign as today); if both absent, use `FallbackCredentialsFactory.GetCredentials()` (AWSSDK default chain: task role → IMDSv2) and drop only those two from the missing-keys fail-closed list (Endpoint/Bucket/Region stay required; a half-set pair still fails closed naming both). Presigned URLs keep working via the chain's URL signer. On AWS set `Storage__S3__Endpoint=https://s3.<region>.amazonaws.com`, `Storage__S3__ForcePathStyle=false`, omit keys.
- Tests: in `tests/Facilitator.Tests` Storage folder — (a) ctor with no keys does not throw and selects default chain (set `AWS_ACCESS_KEY_ID`/`AWS_SECRET_ACCESS_KEY` env in-test), (b) half-set pair throws fail-closed naming both keys, (c) existing static-key tests unchanged. Run `dotnet test --filter "FullyQualifiedName~Storage"`.
- This lands first / independently: everything else consumes it so infra ships zero static keys.

## Step 3 — Components (`examples/aws/lib/` — reusable, teams adopt parts)

Everything teams plausibly pre-own is **create-or-reference** (prop carries the imported id/arn); everything team-local infra is **always created**. One construct per block; stacks compose them.

- `Vpc` — props `existing?: {vpcId, privateSubnetIds}`. Create path: `Vpc` L2, 2 AZs, private subnets only, NAT gateway (prop `natMode: 'gateway'|'public'`, gateway = VPC NAT Gateway in one AZ, cheaper demo), gateway endpoint for S3, interface endpoints for Secrets Manager, ECR api+dkr, Logs, Cognito (idp), STS; all endpoints private+`lookupAllowed`. Import path: `Vpc.fromLookup` fields from context. Security-group baseline SG created in either path.
- `Cluster` — ECS `Cluster` per account, Fargate capacity providers, container-insights prop off by default (cost).
- `Database` — RDS Postgres 17 **serverless v2 only** (`DatabaseInstance` serverlessV2 min 0.5 / max 2 ACU props, `multiAz` prop default true, storage encryption default `aws:rds/<region>` key, `DeletionProtection` + `Retain` on prod-flag, `DatabaseProxy` omitted). Secret auto-created by CDK (`Secret` with master key), name `facilitator/db`. No public IP, kernel SG ingress 5432 only.
- `ArtifactBucket` — versioned, SSE-KMS, public access block, lifecycle: expire noncurrent versions (GC seam already kernel-side via `Storage:Gc`), storage-class transitions; server-access logs to a second bucket (or note CW alternative). Created always.
- `Secret` (`SecretRef`) — thin wrapper: created secret, or imported by name/arn (create-or-reference for org-shared secrets). Team enrollment secret is **created with placeholder** value; README runbook: kernel-side admin mints token → operator writes it into `facilitator/team/<name>/enrollment` (`aws secretsmanager put-resource-policy` not needed — manual hand-off by design).
- `Identity` — Cognito `UserPool` (passwordless-capable props), managed login domain, API resource `facilitator-api` + SPA client (public client, PKCE, no implicit) + server client for the kernel's client-credentials/authorization-code flows (mirror `reference/keycloak/realm.json` client set). Props: `federation?: { type: 'oidc'|'saml', ... }` wiring a user-pool identity provider to a corporate IdP (AWS-native front door federating out). Emits `issuer` + `oidcClientId` outputs consumed by `KernelService` env (`identity__oidc__authority` must byte-match the issuer, `identity__oidc__audience=facilitator-api`, plus `ui__oidcAuthority`/`ui__oidcClientId`). Keycloak-on-ECS documented as the 1:1 port of the reference env — not a stack.
- `WebFace` — internet-facing ALB (internet-facing is the point; subnets in public subnets the VPC component creates when `vpc` create-path — if a team/platform VPC is imported with no public subnets, WebFace requires them via props, clear error otherwise): ACM wildcard cert (DNS validation against the referenced existing Route53 zone looked up by `hostedZoneDomain` — fail with explicit message if zone missing; CDK never registers domains), Route53 A-records for `kernelDomain`. Listener rules (exact literals, order matters):
  1. `/{path}` `/api/ingress/*` → kernel TG (public, WAF rate-limited)
  2. `/api/link/v1/*`, `/hubs/link`, `/events`, `/deliveries` → kernel TG (public — this is the link-plane door workspaces/gateways/launcher dial out to; `/health` public)
  3. `/api/admin/*`, `/api/works*`, `/ui-config`, `/` (SPA) → kernel TG **behind forward-auth to Cognito** when `infraAuth: true` (default): ALB `forward` config with Cognito user-pool parameters — SPA intercepted before first FE script; `infraAuth: false` prop skips infra hop, kernel app-level OIDC authz (`identity:authorization` bindings) still enforces. Webhook/link rules never infra-authed.
- `Waf` — WAFv2 web ACL: AWS managed rule groups (KnownBadInputs, IPReputation, SQLi) + rate rule 500 req/5min on `/api/ingress/*` and `/api/link/v1/enroll` (kernel already rate-limits enroll; ALB rate rule protects the limiter). Prop `enableWaf` default true. Separate construct so it's deletable.
- `KernelService` — Fargate service, `desiredCount: 2` (the two-replica shape: `Kernel__ReplicaId` = task-name-derived unique per task, advisory-lock migration `pg_advisory_lock(420001)` makes concurrent migrate safe). Task def: platform task role with **no static keys** — RDS secret read, S3 bucket-scoped policy (Step 2 chain), Logs, CloudWatch OTLP publish. Env mirrors `reference/config/facilitator.env` 1:1 (`ConnectionStrings__Facilitator` from secret, `Storage__Provider=s3` + no-key S3 settings, `Otel__Endpoint`/`OTEL_EXPORTER_OTLP_ENDPOINT`→ADOT sidecar localhost, `Link__HeartbeatSeconds=5`, `Kernel__ReplicaId`, `Config__File` pattern — kernel config JSON shipped as a mounted file from S3 asset or env-injected; use env-injection via task-def `environment`/`secrets`, no file mount). Target-tracking 60% CPU/memory. `PlatformVersion: LATEST_X86_64` (aspnet image arch — confirm against release images; context `images.kernel`).
- `AdotSidecar` — container from public ADOT image (`public.ecr.aws/otel-… adot-collector`, pin tag in package constant + README), config exported to CloudWatch OTLP + X-Ray. Included in `KernelService` and team services only when the observability prop is on (Step 5); task def container is contributed by the `Observability` component so deleting that stack removes the sidecar on next deploy… **simplification actually implemented**: sidecar container presence is a plain prop on `KernelService`/`TeamPlane` (`observability: true|false`), and the `ObservabilityStack` owns only log groups, the OTLP/X-Ray IAM policy fragments (via component-granted inline policies), and alarms. Prop-off = sidecar absent.
- `TeamPlane` — per-team stack body: gateway service + N workspace services as Fargate tasks on the team `Cluster`, **outbound-only** (no ALB — no inbound rule at all; SG egress-only), each pulling its digest-pinned image URI from context env, env `OFAC_KERNEL_URL=https://<kernelDomain>` + link token injected from the team `Secret` (`secrets:` task-def injection, re-enroll on 401 is already SDK law). EFS `FileSystem` (encrypted, `transitEncryption`) + per-service `AccessPoint` (POSIX-owning user per service) mounted at the connector SQLite state path; EFS via IAM auth. Per-team Secrets created with placeholder + documented hand-off (enrollment secret, forge tokens, bot creds).
- `Fleet` — optional (only instantiated via `TeamFleetStack`, Step 7): task definitions (or capacity provider + task-template constraint) the launcher may run, the launcher's RunTask IAM role (scoped: `ecs:RunTask` on those definitions + `iam:PassRole` to the fleet task role only), the fleet task role (Logs + EFS), and the launcher's own service (single Fargate task, restart-once-per-deploy, link-plane dial-out to `https://<kernelDomain>`). Static rules file (see Step 7) is the image-allowlist + network-pinning analog.

## Step 4 — Stacks + app (`examples/aws/bin/app.ts`, `examples/aws/lib/stacks/`)

## Step 7 — Fleet launcher (`examples/aws/fleet-launcher/`, optional non-production showcase)

Provisioning is an **optional team capability**: the compose reference env already rides provisioning as an overlay, and on AWS the whole fleet block is opt-in — env-file team entry `"fleet": true` instantiates `TeamFleetStack`; otherwise no ECS-fleet, no launcher resources exist. The kernel treats a launcher as absent-by-default (`Provision__LauncherEndpoint` unset ⇒ provisioning ops recorded, no envelopes — existing kernel behavior, no kernel change).

New pnpm member. Reimplement the launcher **client contract** exactly as `src/adapters/provisioning-oci` does it (that's the whole point: anything reaching the kernel uses the kernel's existing protocol, and it dials out):
- Enroll `POST /api/link/v1/enroll` (body `{token, endpointId, instanceId, trustMode:"isolated-executor", role:"child"}`) → Bearer link token, refresh-on-401; publish capabilities; receive `org.facilitator.command.provision.start.v1` / `.stop.v1` over SignalR `/hubs/link` (WebSockets-only) via `@ofac/workspace-link` SDK; reply `CommandOutcome` receipts (acked/delivered/rejected law mirroring the oci launcher's `handler.ts`).
- Backend = ECS: `RunTask`/`StopTask` against a cluster from a **static local rules file** (`fleet-rules.json`: `workloadId → { taskDefinition, cluster, subnets?, envAllowlist? }`) — the image-allowlist + network-pinning analog; spec `env` merged into task overrides honoring the kernel's `$NAME` name-indirection law (resolved from launcher's own env, values never cross the wire). Unknown `workloadId` → rejected receipt.
- Runs as one Fargate task **in the team account** (`TeamFleetStack`); the kernel never opens a connection toward the team — provision commands ride the same link plane as every other team workload. README header + code comment: **non-production reference, unsupported, not part of the supported adapter set**; Docker-socket law intentionally not ported.
- `examples/aws/fleet-launcher/Dockerfile` (FROM the pinned node-runtime image pattern of `reference/container/Dockerfile.elastic`); image URI fed to team envs via `images.fleetLauncher`.

## Assumptions & contingencies

- OTLP→CloudWatch custom-metric namespace for the gauges is `facilitator` — **unverified** (no AWS creds exist here). Alarms take the namespace as a stack prop defaulting to `facilitator`; first real deploy confirms/adjusts the prop only.
- Cognito issuer URL shape works as `identity:oidc:authority` byte-match — kernel requires https issuers by default, Cognito issuers are https: fine. If a corporate-IdP federation edge case breaks the byte-match (email-verified domain caveats), fallback: `trustedIssuers` list already supports it; document, don't code.
- If LocalStack's Cognito/RDS mocking rejects a construct-level call during smoke, drop that stack from the smoke set (documented exclusion list in the smoke script), keep synth+snapshot coverage — do not contort the CDK for LocalStack.
- `envs/example.json` ships placeholder accounts; `deployctl` fails with a clear message when a referenced Route53 zone or context account is missing (create-or-reference law applies to VPC/DNS/zone; RDS/S3/secrets/EFS always created).
- The kernel's S3 change may surface presign quirks under the default chain; if so, fall back to keeping static keys as the documented AWS option and mark the chain fallback experimental in README (fallback pre-decided — don't stall).
