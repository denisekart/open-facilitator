# Embedded workflow plane: definitions, sink, instances, strangler, progressive UI

** Slug: `embedded-workflow-plane` **

## Context

`.omp/ideas/embedded-workflow-engine.md` settles on building a small workflow/durability **definition plane** *inside* the Facilitator kernel (external engines ruled out): JSON workflow definitions stored in Postgres, executed by a `WorkflowSink : ISink` on a synthetic kernel channel, riding the existing inbox/outbox loop, command-id idempotency, sweeps, and audit. Governing law: the plane must be a **strict superset** of today's behavior (§5 parity ledger), so migration is a strangler with shadow-mode reconciliation before any arm is switched off. This plan covers §9 in full — skeleton → review-fork shadow → review-fork swap → PR-on-manifest → AssignRules — **plus a composition layer (Phase 6): workflows invoking other workflows, awaiting their output, and resuming, with preemption guarantees** (e.g. *agentic-research* calls *ensure-capacity*, waits for the harness it spun up, continues). UI is progressive and comes **after** the backend phases: read-only flows view (Phase 7) → editor (Phase 8), each stage verified before the next starts.

(`where` matched inside the sink against the envelope, matcher law.) **Work-context resolution (load-bearing: `workflow.stage` rows, `work.*` guard fields, and `works.workflow_instance_id` all need a subject work):** when the trigger envelope carries a `workId` context, that work is the instance's primary work; otherwise the emitter resolves the communication binding exactly like the arms do (`CommunicationBindings` lookup by envelope `source.provider/channel/rootMessageId` — same query as `ProviderEventStore.ReviewArmAsync`'s binding step) and records it; unresolved ⇒ the instance still runs **workless** (`workflow_instances.project`/work refs null, `workflow.stage` rows skipped, guards reading `work.*` evaluate no-match → `fallback` branch), never silently dropped. **Idempotency, exact:** trigger row command id verbatim `wf-trigger:<defId>@<ver>:<triggerOutboxRowId>`; instance id `Uuid5(WorkflowIdentity.TriggerNamespace, $"{defId}@{ver}>{triggerOutboxRowId:N}")` with the namespace constant documented in `WorkflowIdentity.cs` (fixed separators — idTokens contain dots, unjoined concatenation would be ambiguous; the `:`-separated law of `RoutingIntent.cs:55-59`). Applies to every deterministic append (`wf:`, `wf-wake:`, child ids).

### Phase 2 implementation notes (landed; Phase 3 builds on these)
- **Stamp law** (load-bearing beyond optimization): `OutboxRow`/claim now carry `work_id`; the trigger emitter stamps the subject work at emit time (`EmitAsync(db, envelope, subjectWork, ct)`), the review arm calls it INSIDE its transaction with the work the review hit (pre-fork). `WorkflowRunner` prefers `trigger.SubjectWork` over re-resolving (the arm repoints the binding to the successor — a delivery-time lookup would see the wrong subject).
- **Shadow law is executor-level**: the definition's `shadow` flag threads into every executor; emit/approval/escalate/fork-work compute their effect, return a `wouldDo` output, write nothing (`db.Entry(row).State = Detached`). A shadowed instance starts `shadowed`, ADVANCES like running (gate admits `shadowed`), parks as `shadowed` with deadline, terminates as `shadowed` (never `completed`). A wake flips only deadline-bearing parks and keeps `shadowed`.
- **Delivery context law**: the trigger/wake envelope rides EVERY leg of one advance (not just the first) — step templates read `$event.*` at any depth.
- **Guard decide**: a HIT continues via the completed-edge law (no FirstBranch on guard source); a MISS takes `fallback`.
- **Interpolation law**: `${dotted.path|alt.path}` segments inside strings resolve against the context (first hit wins), unresolved → empty. The gallery `review-fork` noteRef reproduces the arm's InputNote sentence exactly.
- **Post-command coercion** (B4 as the schema spells it): a `communication.post` effect from a thread/comment trigger coerces `conversationKind` to `channel` (keys kept).
- **Toggle refreshes the subscription set** synchronously (the admin-toggle law the registry doc-comment promised).
- **`WorkFork.ComputePlan`** (`Kernel/Work/WorkFork.cs`) is the single place the fork's sentences live (objective, reply text/command id, link kind/note, created-detail). Phase 3: the arm's `ForkTerminalAsync` body becomes the plan applier (it keeps minting the successor guid, or adopts the plan's id) and defers to the plane when the definition is enabled-not-shadow.

## Phase 6 — Composition: workflows invoking workflows (await + output hand-off), preemptive

The user-level capability: *agentic research* (workflow A) calls *ensure-capacity* (workflow B), waits for its output, resumes — composable, and impossible to spin out of control. All of it runs on the Phase-1 machinery; the store columns (parent/depth/path/output/end_reason) and the schema constructs (`invoke` step, `invoked` trigger, `output`, `composition`) already landed in Phase 0.

26. **`invoked` trigger + `WorkflowInvoke` step** (`Kernel/Workflows/Steps/InvokeStep.cs`):
   - Parent advance executes `invoke { workflow, version?, inputs, await (default true), timeout (schema-required), onTimeout }`:
     resolves the target definition (pinned explicit `version`, else the target's live enabled version — pinned into the CHILD instance, so mid-flight parent versions can't morph the child);
     child identity deterministic: child instance id = `Uuid5(WorkflowIdentity.InvokeNamespace, $"{parentInstance}:{stepId}")` (same helper file as `ForkWorkId`; a redelivered invoke re-derives the same child id and collides on PK ⇒ exactly-once child, the outbox law verbatim);
     child row written **in the parent's transaction** with `parent_instance_id`, `depth = parent.depth + 1`, `invocation_path = parent.invocation_path + ">" + targetId@ver`, `trigger_event_id` = the parent's trigger (shared provenance), inputs stored as the child's initial step-log row (`step_id = "input"`, `seq = 1`);
     **awaited invoke + parent park commit as ONE transaction** (step row → `status 'running'` with the parked correlation key + `deadline_at = now + timeout`, child row, preemption verdict): the child's wake row can therefore never arrive before the parent is parked — no wake-before-park window exists by construction;
     preemption checks (27) run **before** the child row is written.
   - `await: false` → parent step `done` immediately (child id in its output). **Detached-child lifecycle:** detached children survive a *completed* parent (fire-and-forget is the point of `await: false`) but are cascade-cancelled when the parent FAILS or is CANCELLED (`end_reason 'parent-cancelled'`), enforced by the same recursive walk the awaited case uses.
   - **Race law (wake vs timeout vs operator-cancel):** every transition out of a parked invoke step is a **conditional UPDATE** `SET status=… WHERE instance_id=@i AND step_id=@s AND status='running'` under the per-instance advisory lock; exactly one of {wake row, sweeper timeout, cancel} wins, losers no-op. The wake path additionally re-checks the child's terminal row (already `completed|failed|cancelled`) so a cancel racing a completed child resolves to the child's recorded terminal state, not a lost update.
27. **Preemption law (four guards, checked in one place — `WorkflowPreemption.TryAdmit(childCandidate, defDoc)` — before ANY child row, so a denied invoke has zero side effects):**
   1. **Static cycles:** the invoke-call graph over *enabled* definition versions (`defId@ver → target@pinned-or-live-version`; edges to live-version targets are re-checked at every enable) must be acyclic — validator + a runtime guard on the live snapshot; violation at enable = 422 `composition-cycle` naming the path.
   2. **Chain budget:** `depth ≤ WorkflowLimits.MaxDepth (= 5)`; total entries in the child's `invocation_path ≤ WorkflowLimits.MaxChainInvocations (= 64)`; per-definition occurrence count of each `defId@ver` in the path ≤ that definition's `composition.maxInvocations` (default 20) — self-reference additionally requires `composition.reentrant: true`. Denial end_reason: `'budget-exhausted'` for the per-definition count, `'chain-age-exceeded'` for depth/path overflow (every `end_reason` value is produced by exactly one named guard). Constants in `Kernel/Workflows/WorkflowLimits.cs`.
   3. **Budget breach is a branch, not a crash:** step takes the `failed` edge, `end_reason = 'budget-exhausted'` recorded in the parent's step-log `output`, one `workflow.stage` timeline row on the parent's work ("invoke denied: budget"). Denial never fails an unrelated leg.
   4. **Age + death:** every `invoke` carries a mandatory `timeout` (schema law) → the parent's sweeper pass fires it, cancels the non-terminal descendant subtree, takes `onTimeout`; **cascade cancel** = recursive `parent_instance_id` walk cancelling child instances and only the works each child created (`works.workflow_instance_id` match, non-terminal only — the Phase-1 cancel law, nothing else touched). Operator-cancel of a parent cascades identically with `end_reason = 'parent-cancelled'`; child cancelled/failed ⇒ parent `invoke` step takes the `failed` edge with the child's terminal state in its output.
28. **Completion hand-off (the "wait for its output and resume" hop):** the child's final advance computes its definition's `output.project` (select-law projection over its step log — a definition with no `output` block publishes `{}`), stores it in `workflow_instances.output`, and **in the same transaction** appends an outbox row to `workflow.kernel`: a **real wire event** — new `protocol/json-schema/event.workflow.completed.v1.json` (Phase-0 migration adds it too, so codegen/envelope-validator/CI see it from day one; payload `{instanceId, definitionId, definitionVersion, status: completed|failed|cancelled, output: object}`), type `org.facilitator.event.workflow.completed.v1`, addressed to the child's own `workflow.kernel` row and matched by the sink to the awaiting parent via the parked step's correlation key. Command id of the wake row: `wf-wake:<childInstance>:<status>` (deterministic; PK/command-id collision ⇒ resume exactly once, survives double-notify). Making this a wire schema (instead of an internal type) keeps `KernelOps.AssertEnvelopesValid` green for every outbox row and gives flows an event operators can also trigger other flows from. **Sink discrimination order (one event, two possible meanings):** the sink first attempts *wake correlation* — payload `instanceId` equals some parked step's correlation target AND the payload's `parentInstanceId` identifies the awaiting instance — consuming the row as a wake; only when nothing is parked does the row participate in ordinary `on.event` trigger matching. **Lineage on wake-as-trigger (the spin-out hole this closes):** an instance spawned by a `workflow.completed` trigger is NOT a fresh root — the emitter inherits lineage from the emitting instance: `depth = emitter.depth + 1`, `invocation_path = emitter.invocation_path + ">" + defId@ver`, and the new instance's `deadline_at` is capped by the emit-chain's remaining age (the chain carries one deadline from the root: max total age `WorkflowLimits.MaxChainAge` = 24h default). Without this, A→wake→A chains reset every budget. **Emission discipline:** a completed instance appends its `workflow.completed` row iff (a) a parent is parked on it, or (b) the subscription set contains `workflow.completed` — otherwise no row at all (detached no-op completions don't litter the outbox); either way the child's final step-log row records the would-have-been wake. Parked-wake delivery to a parent that meanwhile failed/cancelled ⇒ row consumed as no-op (the step's conditional UPDATE lost the race — item 26's race law), never requeued. The sink's wake path copies `output` into the parent step's `output`, marks it `done`, continues the parent. Template refs: `$step.<id>.output.output.<jsonPath>` for awaited invokes; `$child.status` for detached ones.
29. **Observability:** `GET /api/admin/workflows/instances/{id}` returns the ancestor chain + direct children; a child's console strip renders parent-first (`invoked by "agentic-research" v2 · step 2/4`); OTel: child-instance id as a span link from the parent invoke-step span (Phase-1 tags already carry the parent's instance id).
30. **Gallery pair (the motivating example, ships as data):**
    - `ensure-capacity` (`on: { invoked: {} }`, `composition: { maxInvocations: 4 }`): `emit command.work.assign` (harness spin-up capability, inputs from the invoke inputs) → `wait assignment.completed` (timeout, `onTimeout` → failed edge) → `output: { project: { endpointId: "$steps.<wait-id>.output.data.endpointId", workId: "$steps.<wait-id>.output.data.workId" } }` (select-law projection over the completed assignment's envelope).
    - `agentic-research` (`on: event provider.mention` + where): `invoke ensure-capacity (await, timeout 15m)` → `emit assign` research capability → `wait assignment.completed` → done. Both `source='gallery'`, `enabled=false`; their descriptions are the documentation of composition.
31. **Verify (composition gate):**
   - xUnit happy path: seed parent trigger; drive dispatcher+sink; assert child created (depth 1, path `parent@1>ensure-capacity@1`), parent parked (`waiting`, deadline set); complete the child's assignment via existing `KernelOps.WalkToCompletedAsync`; wake row lands (commandId exact match), parent resumes exactly once with the child's projected output visible in its step-log row.

event, correlation = key appears in `data`; wake output carries the whole wake
envelope under `wake` — `WakeOutcome`), `approval` (parks on
`approval.decided.v1`, denied/expired take the failed edge), `fork-work` (the
WorkFork shared law, subject = the instance's primary work), `select` incl.
`source:"manifest"` + `defaults` (a constant output field = absent path +
literal default), `fan-out` (per-element emits), `escalate`. Graph is acyclic —
no loops, no condition-retries.

Ship (five):
1. **`fork-on-terminal`** — the WorkFork law as data, invokable by any flow that
   hits a closed work: one `fork-work` step; inputs {note}; output
   {successor} (`fork-work` leg output). Subject work = the child's stamped
   primary work (invoke passes the parent's subject — Phase 6 child-context
   law; without it the leg fails honestly).
2. **`vcs-change-request`** — inputs {repo, head, base?, title?, body?}: `emit
   capability vcs.change_request.create` + `emit.binding branch` (the exact
   pr-on-manifest leg, now a component); then `wait` on
   `org.facilitator.event.provider.change_request.v1` correlated on
   `branch:${input.head}` (the opened-event payload carries the head ref — the
   substring correlation law resolves it, the head-branch resolver's own path);
   output {repo, prBinding} projected from
   `steps.<wait>.output.wake.data.reference.rootMessageId`.
3. **`await-input`** — the reusable "ask a human" pause: `wait` on
   `org.facilitator.event.assignment.input.required.v1` correlated on a named
   `$input.correlateKey`, `timeout` input; output {text} projected from the wake
   envelope (`wake.data.text` — check the answering event's field when wiring).
4. **`consent-then-act`** — `approval {question: $input.question, approvers:
   $input.approvers}` → approved edge `emit {command: $input... }` (capability or
   command per input, declared by the caller's inputs), failed edge `escalate`;
   output {decision, effect} from the wake (`wake.data.decision`) + the emit leg
   output.
5. **`announce`** — the thread-ack primitive the assign-rule template inlines:
   `emit {command: communication.post.v1, inputs:{text: $input.text}}` (the
   work-scoped addressing law routes it to the work's live conversation);
   output {posted} via the defaults trick (constant true).
   Follow-up once the shelf lands: the derived `assign-rule-*` copies may invoke
   announce instead of inlining the ack (same behavior, shelf dogfooded).

Skip (mechanism honesty, recorded verdicts): **await-capacity** (the flow cannot
name the chosen endpointId — the funnel decides after the flow ends; no-capacity
already auto-triggers provisioning and the audit carries the reason; a component
would output a null it cannot know); **work-status-gate** (state transitions are
TIMELINE kinds, not wire events — a wait has nothing to park on; a re-check loop
needs a cyclic graph, forbidden); **timer-retry** (acyclic palette: fan-out would
emit unconditionally, not on-failure; a `retry` combinator is a palette change,
not a component).

   walk every stored definition's invoke targets (store query, cycle over the

4. Tests: one parameterized xUnit file (`WorkflowComponentTests`), one case per
   component: store + validate + enable, a minimal parent flow

   assert the component child's projected `output` matches the documented
   shape; plus the gallery enumeration update (`WorkflowDefinitionTests.cs:327`

5. Wire one real invocation end-to-end once (announce inside a derived
